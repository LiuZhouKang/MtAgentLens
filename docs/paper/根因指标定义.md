# 根因定位指标定义（回应意见 2 后半 + 具体意见"根因定位评估偏弱"）

> 实现：`compare/tools/root_cause_metrics.py`（schema `mtagentlens.root-cause-metrics/2`），
> 单测：`compare/tests/test_root_cause_metrics.py`。schema /2 修正分支图深度定义；
> /1 的边数量差不是 DAG 深度，历史结果不可混用。运行级预测导出、独立 AI 参考与真实评估仍须闭环，
> 当前没有可报告的运行根因准确率。旧 Type C 在当前分类中为 B，样本数以冻结 cohort 为准。

## 1. 输入

每个 run 一条参考（GT）与一条预测：

| 字段 | 参考 `RootCauseReference` | 预测 `RootCausePrediction` |
|---|---|---|
| `run_id` | 必填，与预测集合**精确匹配** | 必填 |
| `root_agent` / `ranked_agents` | GT 根因 agent | 系统给出的根因候选**排序**（最优在前） |
| `entry_point` | GT 入口（如 `fixture:docs.md`、具体工具调用） | 预测入口，可为 `null` |
| `chain` | GT 因果 DAG，事件实例间有向边 `(from, to)` | 预测链（边集合比较，顺序不影响 P/R） |
| `boundary_types` | GT 越界类型集合 | 预测类型集合 |

严格校验：run id 多/少/重复、空 root、畸形边、排序内重复 agent 都直接 `ValueError`——
不允许"静默丢样本"或"补 0"。

## 2. 指标

| 指标 | 定义 | 空标签时 |
|---|---|---|
| RootAgent@1 | GT 根因 agent 是否排在预测第 1 | —（根因必填） |
| RootAgent@3 | 是否在 top-3 | — |
| MRR | GT 根因 agent 排名的倒数（缺失记 0） | — |
| EntryPoint Accuracy | 预测入口 == GT 入口的比例 | `None` |
| Chain Link P / R / F1 | 预测边集合 vs GT 边集合；P=交集/预测数，R=交集/GT 数 | `None` |
| Chain Depth MAE | 平均 \|预测最长有向路径长度 − GT 最长有向路径长度\|（长度以边计） | 参考空链为未标注，返回 `None`；已标参考下预测空链按深度 0 计 |
| Boundary-type Accuracy | 预测类型集合 vs GT 的 **Jaccard** | `None` |
| missing_root_predictions | GT 根因不在候选排序中的 run 数（单列，不混入其他指标解释） | — |

设计原则：

1. **缺失标签 ≠ 0 分**：没有 GT 的指标返回 `None`，避免"没标注"被读成"很差"或"满分"；
2. **排序与集合分离**：根因用排序指标（@1/@3/MRR），链用集合 P/R（边序不影响）；
3. **分母严格**：run id 必须两侧精确相等，E6 的样本数就是分母，不做事后剔除；
4. **失败可解释**：`missing_root_predictions` 单独报告，配合错误分析（委派链/共谋环/影子智能体）；
5. **@3/MRR 需要冻结排序**：归因内核的 `ranked_agents` 只在单 writer 时给出一个候选，多 writer 为 `None`。
   只要存在非空排序不是冻结的确定性排序（`RootCausePrediction.ranked_from_frozen_ordering=False`），
   `evaluate_root_cause` 就返回 `root_agent_at_3=None`、`mrr=None`、`ranking_reported=False`，
   报告里必须写"top-k 未报告"，**不得**用退化排序凑 @3/MRR，也不得把 `None` 读成 0。
   多候选排序若未声明冻结（或多 writer 直接拼排名）会被 `ValueError` 拒绝。

## 3. E6 的落地条件与顺序

1. 绑定冻结输入、构建与配置，保留每次真实采集的原始证据；当前设计级 proposal 不能作为运行真值。
2. 从 eBPF 证据约束的预测导出根因候选、入口和有向事件 DAG；不得凭显示顺序创造因果边，不得将重复 actor ID 直接当事件实例 ID。
3. 三个 fresh AI 标注会话与独立裁决只读参考材料，不读 detector 输出；如实标为 AI 参考，无人工签字、人工金标或 κ。证据不足的字段保留 unknown，并报告参考覆盖率。
4. 在已标注运行 cohort 上运行 `evaluate_root_cause(references, predictions)`；不为凑 @3 发明排序。当前接口要求参考 root 已知，未知参考须在上游单列覆盖率，不能静默丢弃。
5. 链允许分支、汇合与不相连的已证实切片，深度取最长有向路径；有向环直接拒绝。actor 循环委派须展开为不同事件实例后评估。
6. 按拓扑分组做错误分析。预测缺失计失误，参考缺失单列，不将候选根因或图规模当准确率。

> `missing_root_predictions`；案例保留用于机制解释。**在 E6 运行前，任何根因准确率数字
> 都不得出现在论文中。**
