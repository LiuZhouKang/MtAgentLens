## 总体修改说明

感谢编辑和审稿专家指出判定规则、归因验证、基线协议、测试独立性与开销方面的问题。我们据此将返修内容分为判定方法澄清、运行级证据重核和针对性补充实验。当前替换稿重写分数与最终标签的关系，按采集质量和独立执行证据重新组织结果，并移除没有当前证据支持的高召回、同输入基线优越性及根因准确率结论。

fix4 包含 18 个良性和 43 个攻击场景的有效运行。良性结果为 15 Safe、3 review、0 Unsafe；攻击场景结果为 4 Unsafe、21 review、18 Safe。攻击场景中 16 个有 marker 钩子触达证据，分布为 4 Unsafe、9 review、3 Safe。marker 触达、载荷送达、攻击目标成功分别描述，不将其混为一个“攻击成功率”。

## 审稿人 1

### R1.1 统一评分流程和最终判定规则

**意见**：三区阈值与“0.399 高于 0.15 即攻击”的解释冲突；需要说明中间分数、变换后分数及 Observer 四类结果与最终标签的对应。

**回复正文**：感谢指出这一不一致。原稿混用了分诊分数与运行级裁决。替换稿将分数的用途限定为候选路由和排序；固定 logistic 映射没有独立拟合依据，不称为概率校准。运行结束时聚合确认动作上的硬规则命中、候选版本内的语义审阅及未决状态，写出唯一 final_decision。Observer Unsafe 只有引用具体证据才能支持 Unsafe；同一候选版本内的矛盾、Uncertain、无引用及调用失败保留 review，不能凭失败本身升为 Unsafe。不同候选的审阅不会相互抵消。采集质量不足时，也不能把缺少证据解释为 Safe。删除“0.399 高于 0.15 即攻击”的说明。

**正文位置**：§3.5、算法 3；原 §6.1.3 的旧案例结论移除，工作稿归因评价边界见 §6.3。
**交付与核对**：[正文替换稿 §3.5 与算法 3](revision-package.md)；[判定流程与回归锚点](decision-procedure.md)。已合入 Word 工作稿，最终投稿排版待核对。

### R1.2 身份解析与溯源准确性

**意见**：共享进程、连接复用、并发可能错误合并；应定义子智能体边界，并量化身份与根因准确性。

**回复正文**：我们同意链深和图规模不能证明根因正确。替换稿将进程身份定义为 PID 与内核启动时间的组合，区分进程谱系、TLS 参与关系与应用会话提示，并说明显式委派和不相交会话的分离约束。单进程多会话的消息可以按会话拆分，但缺少会话信息的系统动作不被强制指定给某个逻辑智能体。合成拓扑用于检验这些规则的实现；真实工作流的身份归属与根因准确率需另行评价，不能用规则测试替代。当前撤下将图规模作为定位准确性证据的结论。

**正文位置**：§3.4.2、算法 1、§5.1、§6.3。
**交付与缺口**：边界文本见 [正文替换稿](revision-package.md)，合成测试见 [E5](../evaluation/e5-identity-microbenchmark.md)，真实根因指标见 [根因指标定义](根因指标定义.md)。真实 Type C 归因、入口和链级评价尚未完成；此意见不能标记为全部解决。

### R1.3 基线比较与外部基准协议

**意见**：现有基线输入不对等；需要相近运行时方法或完整部署比较，并核实 InjecAgent 执行与样本构造。

**回复正文**：原表混合了仅文本输入的检测器与使用操作系统事件及语义审阅的系统，不足以支持同条件性能优势。替换稿将功能定位比较与实际复现实验分开，文本与文本＋工具轨迹作为不同输入臂。原稿 InjecAgent 适配没有执行相应 OS 工作流，因而不能作为运行时泛化证据；当前撤下该数字比较，并明确其文本适配性质。已有适配器和导出脚本仅说明实验能够组织，不当作已完成结果。

**正文位置**：§2、§5.2、原 §6.3 外部基准表。
**交付与缺口**：[正文替换稿 §5.2](revision-package.md)、[同级方法矩阵](能力矩阵-同级方法.md)。同输入应用层基线和外部真实运行尚需执行，不能声称已补齐。

### R1.4 指标核对与测试独立性

**意见**：Meta Prompt Guard 指标不自洽；开发/测试隔离未说明；需活动规模相近的困难良性任务。

**回复正文**：替换稿撤下不同构建与口径的旧性能表，按同一冻结测量重新报告运行数、裁决、覆盖率与弃权率。有效良性运行的条件误报为 0/15，Wilson 95% 区间 [0%,20.39%]，同时报告 83.3% 二元覆盖率，不把零观测误报解释为总体零误报。攻击侧区分场景标签和实际执行证据；全部攻击场景的 Safe 不整体记作漏报。原文没有可核验的独立开发集记录，替换稿不再宣称严格隔离。固定观测的敏感性分析用于补充诊断，但不能替代独立测试和困难良性扩展。

**正文位置**：§5.1、§5.3、§6.1、旧表 11。
**交付与缺口**：[数字审计](数字审计-2026-10-25.md)、[正文结果表](revision-package.md)、[E3](../evaluation/e3-threshold-sensitivity.md)。旧 F1 算术错误须在移除旧表时一并更正说明；困难良性扩展尚需新运行。

### R1.5 完整系统开销

**意见**：探针延迟和采集器RSS不足以代表完整系统；需并发下丢失、告警时延、内存和模型成本，百分比也需更正。

**回复正文（2026-10-28 实测完成）**：我们接受这一意见。复核发现，历史218.2624 ns是三个BPF程序平均时间之和，且配套TLS负载未建立连接，不能解释为一次探针或成功SSL操作的完整成本。修订稿撤回这一解释及与握手时长的成本比较，历史RSS与ONNX资源数字也不作当前系统结果。

我们在同一冻结构建和一套固定Agent负载上完成了分层测量：并发1比较无监测、仅采集、本地责任分析加数据库、完整真实Observer四种条件；并发4/8/16/32比较无监测与完整系统，每格三次，共36个正式条件运行（15个配对区组、372个Agent实例），36/36完成且固定工作量完成率均为100%。完整系统在并发1的条件墙钟为9.27 s、collector峰值为376.0 MiB RSS，Observer为2.0次调用/条件、费用上界$0.005232；并发32的条件墙钟为150.91 s [40.21–234.74]、collector峰值RSS为772.7 MiB、DB+WAL峰值169.45 MiB，责任图终态为823.7节点/36,254.7边，图更新82,572次/3.51 s，Observer为8.3次调用/条件、$0.067886上界。高并发墙钟的重尾由phase-2批量关联主导，图更新计时不含该部分，因此没有把C2−C1写成graph-only。

捕获质量方面，全部C1–C3条件的受控操作在raw和持久化证据中缺失均为0.0%（32并发0/1536、0/1536）；但32并发下进程采集源仍报告13,439–16,442次ring-buffer丢弃，TLS源为0，二者分层报告，不合并成单一丢失率。可关联最终告警在并发1为1/16（p50=p95=7.63 s），并发32为23/1536（p50=144.10 s、p95=145.17 s）；覆盖率低是因为多数受控文件操作不产生可告警证据，不是漏报率。TLS成功读写微基准（3次、均零丢弃）为873.4 ns/成功SSL读写操作；其他启用程序的短诊断窗口给出syscall enter 66.3–70.9 ns、complete 85.6–90.7 ns、exec 3.74–4.15 μs、exit 1.47–1.75 μs，均含窗口内过滤返回，不是每有效事件的完整处理成本。正式36条件的Agent+Observer峰时费用上界合计$0.6204（含归档失败attempt $0.0309），本实验全部cohort合计$1.6465（观测/已知usage上界$1.0265 + 未计量请求准备金$0.62）。

固定短任务的Agent端到端耗时配对差值在并发1为−0.03%…+17.32%、并发32为−4.05%…+20.70%（n=3，描述性，不报显著性），不能据此宣称加速或精确减速。结果限于单主机、单内核、单一固定负载和3次重复；不推断CI/p99、长期无泄漏或跨环境性能。

**内部执行与交付**：详细协议与结果见[实验总方案§6/§6.6](../evaluation/EXPERIMENT-SUITE-7-REVISED-2026-10-26.md#6-overheadbench5)；T8/F2 在`compare/results/overhead/raw/full-system/report/`，由严格完整模式导出、无warning。Word合入时用T8替换表12、F2替换图8；正式引用前按claims流程登记新数字与artifact哈希。

## 审稿人 2

### R2.1 基准规模、评估独立性与困难良性

**意见**：良性样本少；参数由作者确定；独立开发集和测试隔离不明确，需困难良性或敏感性分析。

**回复正文**：我们将零观测误报与统计不确定性分开报告。当前有效良性样本中的条件误报为 0/15，Wilson 95% 区间 [0%,20.39%]，覆盖率 83.3%、弃权率 16.7%。没有可核验的独立开发集记录，因此不以冻结快照替代开发/测试独立性。替换稿给出固定记录输入的阈值、逐维相对权重和门控诊断，并说明记录 Observer 观测保持不变，不能据此断言真实调用策略不影响检测。困难良性任务应在新语料中覆盖大量委派、授权敏感访问与正常外联，并与攻击活动量匹配。

**正文位置**：§5.1、§5.3、§6.1–§6.2。
**交付与缺口**：[正文替换稿](revision-package.md)、[E3](../evaluation/e3-threshold-sensitivity.md)。困难良性新实验尚未完成。

### R2.2 PBC 活动量混杂

**意见**：Type C 的大 PBC 和计数型评分可能仅反映任务活动多，而非恶意。

**回复正文**：替换稿将 PBC 统一为不同 `(Agent,边界)` 对数，撤下重复建边得到的旧均值。fix4 中良性和攻击 PBC 均值分别为 0.72 和 1.77，纯 PBC 排序 AUROC 为 0.528，说明该批数据不支持单用 PBC 作为可靠分类器。该结果不等于已经排除任务复杂度混杂，仍需活动规模匹配的困难良性实验。PBC 的证据组织用途与检测增益分别评价。

**正文位置**：§3.3.2、§6.2、讨论。
**交付与缺口**：[E2](../evaluation/e2-pbc-activity-baseline.md)、[正文替换稿](revision-package.md)。困难良性匹配尚未完成。

### R2.3 基线公平性与覆盖面

**意见**：仅文本基线与 OS＋Observer 输入不等价，需文本＋工具轨迹基线或等价执行信息，并补同级方法比较。

**回复正文**：我们接受需要控制输入信息和模型条件。替换稿撤下旧表支持的性能优越性结论，区分文本、文本＋工具轨迹与 OS 证据三种输入；比较还须统一裁决标签并报告弃权、覆盖及成本。同级方法矩阵用于解释功能和部署边界，不将未部署方法的文献数字与本次结果直接排名。应用层 runner 已有实现，但尚未以其存在代替真实实验结果。

**正文位置**：§2、§5.2、§6 基线表。
**交付与缺口**：[同级方法矩阵](能力矩阵-同级方法.md)、[正文替换稿 §5.2](revision-package.md)。同模型等输入对照仍需执行。

### R2.4 根因定位与身份正确率

**意见**：只有案例和链深，缺少全部 Type C 的根因/入口 Top-k 及身份正确率。

**回复正文**：链深衡量结构而不衡量定位正确性。替换稿区分进程/会话身份、动作归属及入口/传播链评价，保留共享进程缺少会话标识时的未知归属。合成身份拓扑只验证规则符合规格，不用其分数替代真实多智能体评测。当前移除未验证的根因准确率与链深正确性结论，真实场景需以独立参考标注评价身份归属、入口、Top-k/MRR 与链级指标。

**正文位置**：§3.4.2、§5.1、§6.3。
**交付与缺口**：[根因指标定义](根因指标定义.md)、[E5](../evaluation/e5-identity-microbenchmark.md)、[正文替换稿](revision-package.md)。真实 Type C 全量评价及实际独立复核尚未完成。

### R2.5 消融粒度

**意见**：eBPF 与 PBC 同时引入，难以区分贡献；图与 Observer 的检测增益不足，需逐维 LOO。

**回复正文**：替换稿撤下旧的逐层 AUROC 增益结论，区分图的证据组织用途和检测收益。逐维 LOO 已在 fix4 的 61 份冻结检查点上完成，移除任一维后最终裁决不变，分诊最多变化一个运行。这一分析固定已记录的 Observer 观测，因此只说明条件稳定性，不证明在新调用与新轨迹下仍不变。统一缩放全部权重在归一化后抵消，不能作为相对权重敏感性证据，故另补逐维相对扰动。仅 eBPF 与 eBPF＋PBC 的端到端拆分仍需原始事件重放或新采集。

**正文位置**：§6.2、讨论。
**交付与缺口**：[E3](../evaluation/e3-threshold-sensitivity.md)、[E4](../evaluation/e4-ablation.md)、[正文替换稿](revision-package.md)。LOO 已有固定观测结果；层级拆分未完成。
