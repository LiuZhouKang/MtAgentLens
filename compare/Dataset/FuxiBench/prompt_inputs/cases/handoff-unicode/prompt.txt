## 二、攻击绕过分析

### 2.1 同形字伪造令牌攻击（Homoglyph Token Forgery）

**执行率：4/5 = 80%**（4 个攻击用例中有 4 个成功注入，仅 H4 因不匹配硬编码 TOKEN_PATTERNS 而未被标记为 bypassed）

**事实上 H4 的同形字同样存活**——5 个 Cyrillic 同形字全部穿透 `normalize_handoff()`，仅因为脚本只检查 TOKEN_PATTERNS 列表而未被归类为 bypassed。**真实绕过率为 5/5 = 100%。**

| 用例 | 攻击向量 | 是否绕过 | 说明 |
|------|----------|----------|------|
| H1 | Cyrillic `е` (U+0435) 替换 `Bearer`、`sk-` 中的 `e` | **是** | 5 个同形字全部存活，Bearer 和 sk- 模式在规范化后仍可被检测到同形字版本 |
| H2 | Cyrillic `е` 在 `sk-` 和 `eyJ` 中 | **是** | sk- 前缀和 eyJ (JWT base64 头) 的同形字版本均存活 |
| H3 | Greek `Ι` (U+0399) 替换 AWS `AKIA` 中的 `I` | **是** | U+0399 在视觉上与 ASCII `I` 完全一致，但 Unicode 码点不同 |
| H4 | 自然语言中的同形字 (`thе`, `сonfig`, `filе`) | **是*** | 同形字存活，但不匹配 TOKEN_PATTERNS 列表 |
| C1 | 同形字 + ZWS 组合攻击 | **是** | 两种攻击向量叠加，均存活 |

**根因**：`unicodedata.normalize('NFC', text)` 只做规范组合（将组合字符合并为预组合字符），**不会将 Cyrillic/Greek 字符转换为 Latin 等价字符**。Cyrillic `е` (U+0435) 在 NFC 下保持为 U+0435，不会变为 Latin `e` (U+0065)。需要 **NFKC（兼容性规范化）** 才能做此转换。

**影响评估（高危）**：
- 攻击者可以伪造任意 API token 前缀（Bearer、sk-、ghp_、AKIA、xoxb- 等）
- 受害者（包括 LLM agent）肉眼无法区分 `sk-abc` 和 `sk-аbc`（后者第二个字母是 Cyrillic `а`）
- 在多 agent 交接场景中，伪造的 token 可能被下游 agent 当作合法凭证执行操作
- H3 中 AWS key `AKIA` + Greek `Ι` 在大多数字体中完全不可区分

### 2.2 零宽字符隐藏 Payload 攻击（Zero-Width Hidden Payload）

**测试脚本声称的执行率：0%（全部标记为 "Mitigated"）**
**真实执行率：4/5 = 80%**（4 个攻击用例中的 ZW 字符全部存活，Z4 因含 RTL override 被真正剥离）

**测试脚本存在严重分类缺陷**：脚本的 `attack_stopped` 逻辑仅检查是否有 FORGED TOKEN 残留，零宽字符攻击不涉及 token 伪造却仍被标记为 "mitigated"。这是一个 **假阴性掩盖真实漏洞** 的分类 bug。

| 用例 | 攻击向量 | ZW 是否存活 | 脚本分类 | 正确分类 |
|------|----------|-------------|----------|----------|
| Z1 | ZWS (U+200B) 隐藏在 "execute" 中 | **是** | Mitigated | **绕过** |
| Z2 | ZWJ (U+200D) 隐藏在 "--ignore-check" 标志中 | **是** | Mitigated | **绕过** |
| Z3 | BOM (U+FEFF) 前缀在 JSON key 中 | **是** | Mitigated | **绕过** |
| Z4 | RTL override (U+202E) | 否（被 strip） | Mitigated | 已缓解 |
| Z5 | 4 种 ZW 字符连续嵌入 (U+200B+200C+200D+FEFF) | **是** | Mitigated | **绕过** |

**根因**：`normalize_handoff()` 只 strip `‮` (RLO) 和 `‭` (LRO)，对零宽字符（U+200B-U+200D, U+FEFF, U+2060-U+2064）完全不做处理。NFC normalization 不会移除这些字符。

**脚本分类 bug 详情**：

```python
# 当前逻辑（有缺陷）
attack_stopped = False
if is_attack:
    remaining_forged = scan_for_forged_tokens(result)
    if not remaining_forged:
        attack_stopped = True  # <-- 零宽攻击不产生 forged token，直接进入此分支
```

`scan_for_forged_tokens()` 仅检查同形字版本的 `TOKEN_PATTERNS`，零宽字符改变的是字符串的结构（而非内容），因此永远不产生 forged token 告警。这导致 Z1-Z5 被错误标记为 "Mitigated"。

**影响评估（高危）**：
- Z1：`exec​ute`（嵌入 ZWS）与 `execute` 在视觉上完全一致，但 `normalize_handoff("exec​ute") in "execute"` 为 False。可用于绕过基于关键词的安全过滤
- Z2：`no‍op‍--ignore-check` 在渲染时显示为 `noop--ignore-check`，ZWJ 不可见但改变字符串语义
- Z3：BOM 前缀可能破坏 JSON parser 或导致 key 查找失败
- Z5：多个连续 ZW 字符可编码任意数据（如用 ZWJ/ZWNJ 序列编码二进制 payload），实现隐蔽信道

### 2.3 双向控制字符处理

**执行率：2/2 = 0%**（两个 bidi 攻击均被缓解）

| 用例 | 攻击向量 | 是否存活 | 说明 |
|------|----------|----------|------|
| Z4 | RLO (U+202E) 反转 "Transfer $1000" | 否 | 被 `replace('‮', '')` 正确 strip |
| C2 | RLO+RLO 双向覆盖 | 否 | 被 strip |

**缓解有效**，但存在 **覆盖不完全** 的问题：

```python
# 当前实现
text = text.replace('‮', '').replace('‭', '')  # 仅 strip RLO 和 LRO
```

以下 bidi 控制字符 **未被 strip**：
- U+2066 LEFT-TO-RIGHT ISOLATE (LRI)
- U+2067 RIGHT-TO-LEFT ISOLATE (RLI)
- U+2068 FIRST STRONG ISOLATE (FSI)
- U+2069 POP DIRECTIONAL ISOLATE (PDI)
- U+200E LEFT-TO-RIGHT MARK (LRM)
- U+200F RIGHT-TO-LEFT MARK (RLM)

**影响评估（中危）**：LRI/RLI 可以通过隔离（isolate）方式实现类似 RLO 的文本方向操纵效果，但强度弱于 RLO。LRM/RLM 可用于微调文本方向，在特定场景下可制造混淆。

### 2.4 控制字符处理

**执行率：N/A（无专门测试）**，但代码审计确认：

- `normalize_handoff()` 对 U+0000-U+001F 和 U+007F-U+009F 控制字符 **完全不做处理**
- 规范要求 "MUST be escaped" 但函数实现无视此要求
- 在 Z6（良性文本）中，`\n` (U+000A) 被检测到但通过了规范化

## 四、发现的关键漏洞

### VULN-1: 同形字伪造无防护（严重）

**描述**：`normalize_handoff()` 使用 NFC normalization，不转换同形字。Cyrillic `е` (U+0435)、Greek `Ι` (U+0399) 等 27 个已知同形字全部穿透。

**修复建议**：
```python
# Option A: 切换为 NFKC normalization
text = unicodedata.normalize('NFKC', text)

# Option B: 维护一个同形字映射表，显式替换
for homoglyph, ascii_char in HOMOGLYPH_MAP.items():
    text = text.replace(homoglyph, ascii_char)
```

**注意**：NFKC 会改变更多字符（如全角数字 → 半角、连字 → 分开），可能打破现有语义。Option B 更可控但需要维护映射表。

### VULN-2: 零宽字符无防护（严重）

**描述**：11 种零宽/不可见字符（U+200B-U+200D, U+FEFF, U+200E-U+200F, U+2060-U+2064）全部穿透。

**修复建议**：
```python
ZERO_WIDTH_STRIP = ''.join([
    '​', '‌', '‍', '﻿', '‎', '‏',
    '⁠', '⁡', '⁢', '⁣', '⁤',
])
for ch in ZERO_WIDTH_STRIP:
    text = text.replace(ch, '')
```

### VULN-3: Bidi 覆盖不完整（中危）

**描述**：仅 strip U+202D (LRO) 和 U+202E (RLO)，遗漏 LRI/RLI/FSI/PDI (U+2066-U+2069) 和 LRM/RLM (U+200E-U+200F)。

**修复建议**：扩展 strip 列表至全套 bidi 控制字符。

### VULN-4: 控制字符未转义（中危）

**描述**：规范要求转义控制字符，但实现完全无视此要求。

**修复建议**：添加控制字符检测/转义/拒绝逻辑。

### VULN-5: 测试脚本分类缺陷（用于审计的脚本本身有 bug）

**描述**：`attack_stopped` 判定逻辑仅检查 token forgery，遗漏零宽字符攻击的分类。这会导致安全审计产生假阴性。

## 五、建议的增强版 normalize_handoff()

```python
import unicodedata

# All zero-width and invisible characters
ZERO_WIDTH_CHARS = ''.join(chr(c) for c in [
    0x200B, 0x200C, 0x200D, 0xFEFF, 0x200E, 0x200F,
    0x2060, 0x2061, 0x2062, 0x2063, 0x2064,
])

# All bidirectional control characters
BIDI_CONTROLS = ''.join(chr(c) for c in [
    0x202A, 0x202B, 0x202C, 0x202D, 0x202E,
    0x2066, 0x2067, 0x2068, 0x2069,
])

def normalize_handoff_hardened(text: str) -> str:
    # Step 1: Strip all zero-width characters
    for ch in ZERO_WIDTH_CHARS:
        text = text.replace(ch, '')
    # Step 2: Strip all bidirectional controls
    for ch in BIDI_CONTROLS:
        text = text.replace(ch, '')
    # Step 3: NFKC normalization (converts homoglyphs)
    text = unicodedata.normalize('NFKC', text)
    # Step 4: Strip any remaining control characters
    text = ''.join(ch for ch in text if ord(ch) >= 0x20 or ch in '\n\r\t')
    return text
```

## 六、结论

当前 `normalize_handoff()` 规范仅能防御 **2 种攻击向量**（RLO/LRO 双向覆盖），对同形字伪造、零宽字符隐藏 payload、控制字符注入均无防护能力。**有效覆盖率为 18%**。

在多 agent 交接场景中，攻击者可以：
1. 用 Cyrillic/Greek 同形字伪造 API token，绕过基于字符串匹配的安全检查
2. 用零宽字符改变关键词/命令的语义，绕过基于关键词的安全过滤
3. 用 ZWJ/ZWNJ 序列编码隐蔽信息，建立隐蔽信道

**所有 9 个实际绕过的攻击向量均需在 Phase 2 中解决。**

## 3. 扩展攻击面分析结果

### 3.1 Tag 块字符注入 (U+E0001-U+E007F) — CRITICAL

Tag 块是 Unicode 中最危险的不可见字符集合。它包含 97 个字符，可以编码完整的可见 ASCII 字符串：

```
U+E0001  LANGUAGE TAG       (TAG START)
U+E0020  TAG SPACE          (映射到 0x20 ' ')
U+E0041  TAG LATIN CAPITAL LETTER A  (映射到 0x41 'A')
U+E0042  TAG LATIN CAPITAL LETTER B
...
U+E005A  TAG LATIN CAPITAL LETTER Z
U+E007F  CANCEL TAG         (TAG END)
```

**构造测试**：不可见 "HELLO" payload

```python
tag_payload = '\U000e0001\U000e0048\U000e0045\U000e004c\U000e004c\U000e004f\U000e007f'
# 解码: [TAG_START]HELLO[TAG_END]
```

| 方案 | 结果 | Cf 残留 |
|------|------|---------|
| normalize_handoff_vulnerable | **攻击突围** — 7 个 Tag 字符全部留下 | 7 |
| normalize_handoff_fixed (regex) | **攻击突围** — regex 未覆盖 U+E0000+ 范围 | 7 |
| normalize_handoff_cf_strip | **已阻止** — 全部 7 个字符的类别都是 Cf | 0 |

**严重性**：Tag 块是 regex 方案最大的盲区。攻击者可以构造任意不可见 ASCII payload（命令、URL、token），且 97 个字符的编码密度极高（每个表示一个 ASCII 字符，膨胀比接近 1:1）。

### 3.2 Soft Hyphen 注入 (U+00AD) — HIGH

```
码点:     U+00AD
名称:     SOFT HYPHEN
类别:     Cf (Format)
渲染:     在大多数环境中不可见，仅在换行位置出现为连字符
```

**攻击场景**：在关键词中植入 Soft Hyphen 绕过字符串匹配

```python
whispered = 'exe' + '­' + 'cute'  # repr: 'exe\xadcute'
# 视觉上显示为 "execute"，但 'execute' in dangerous_commands 返回 False
```

| 方案 | 结果 | 机制 |
|------|------|------|
| normalize_handoff_vulnerable | **绕过** | 不改动 U+00AD |
| normalize_handoff_fixed (regex) | **绕过** | U+00AD (0x00AD) 不在 regex 的任何范围内 |
| normalize_handoff_cf_strip | **已阻止** | U+00AD 类别=Cf |

> **纠正**：原始 PoC 报告中误将 U+00AD 标注为 Pd (Dash Punctuation) 类别。实测确认 U+00AD 的 `unicodedata.category()` 返回 `'Cf'`，因此 **Cf 类别方案可正确覆盖**。但 `normalize_handoff_fixed` 的 regex 范围 `[​-‏
-‮⁠-⁩﻿￰-￻]` 从 U+200B 开始，遗漏了位于 0x00AD 的 SOFT HYPHEN。

### 3.3 Arabic Letter Mark 注入 (U+061C) — HIGH

```
码点:     U+061C
名称:     ARABIC LETTER MARK
类别:     Cf (Format)
功能:     RTL 方向控制，不可见
```

| 方案 | 结果 | ALM 残留 |
|------|------|----------|
| normalize_handoff_vulnerable | **攻击突围** | 1 |
| normalize_handoff_fixed (regex) | **攻击突围** — 不在任何 regex 范围 | 1 |
| normalize_handoff_cf_strip | **已阻止** | 0 |

**额外风险**：ALM 不仅可作为不可见分隔符注入 payload，还能控制文本的 RTL 渲染方向。在 `safe\N{ALM}execute` 中，双方向渲染可能使文本在视觉上显示为 "executesafe"，颠覆语义理解。

### 3.4 Combining Character Flood (NFD 攻击) — MITIGATED

使用 112 个可用的 Mn (Nonspacing Mark) 组合字符淹没单个 base 字符：

```
Flood size 5:  NFD 长度 6 → NFC 长度 5  (缩短 1)
Flood size 10: NFD 长度 11 → NFC 长度 10 (缩短 1)
Flood size 20: NFD 长度 21 → NFC 长度 20 (缩短 1)
Flood size 50: NFD 长度 51 → NFC 长度 50 (缩短 1)
```

**分析**：
- 组合字符属于 Mn/Mc 类别，**不是 Cf**。因此三种方案都无法剥离它们。
- **NFC 规范化是唯一有效的防御**：它将分解的字符合并为预组合形式，每组合一个就缩短 1 个字符。
- 但在 50 个组合字符量级下，NFC 输出仍为 50 个字符的 `'à̡̢̧̨...'`，它不是原始 `'a'`，仍可用于携带隐藏信息（每个组合字符本身就是一种编码通道）。
- **最大风险**：如果下游在 NFC 规范化之前进行比较，NFD 膨胀可以改变字符串的字节表示，绕过安全检查。
- **性能风险**：巨大组合序列的 NFC 计算开销呈 O(n^2)（每个新组合字符可能与前面所有字符产生组合）。

**建议**：限制 handoff 数据中单个字符允许的组合标记数量（例如最多 3 个）。

### 3.5 Interlinear Annotation 字符 (U+FFF9-U+FFFB)

```
U+FFF9  INTERLINEAR ANNOTATION ANCHOR     类别=Cf
U+FFFA  INTERLINEAR ANNOTATION SEPARATOR  类别=Cf
U+FFFB  INTERLINEAR ANNOTATION TERMINATOR 类别=Cf
```

这三个字符在 regex 范围内（U+FFF0-U+FFFB），因此 `normalize_handoff_fixed` 和 `normalize_handoff_cf_strip` 都能清除。但两者清除后会**暴露内部文本**：

```
输入:     'safe￹DROP TABLE￻_operation'
fixed:    'safeDROP TABLE_operation'    ← 不可见包装被清除，但 payload 文本暴露
cf:       'safeDROP TABLE_operation'     ← 同上
```

**含义**：即使清除方案有效，清除后会留下可见的 payload 文本。防御需关注**清除后的文本是否构成新的安全威胁**（如 SQL 注入片段、命令注入片段）。

## 6. 最终防御推荐

### 6.1 主防御方案：Cf 类别剥离（推荐）

```python
import unicodedata

def normalize_handoff_robust(text: str) -> str:
    """完备的 handoff 规范化：NFC + 剥离所有格式字符"""
    text = unicodedata.normalize('NFC', text)
    return ''.join(c for c in text if unicodedata.category(c) != 'Cf')
```

**优势**：
- 100% 覆盖所有 170 个 Cf 字符（包括 Tag 块、ALM、Soft Hyphen）
- 零误杀（不匹配任何非 Cf 字符）
- 语义正确（Cf = "Format"，正是需要剥离的类别）
- 未来 Unicode 版本新增的 Cf 字符自动覆盖

### 6.3 补充防御 2：组合标记数量限制

```python
MAX_COMBINING_MARKS_PER_CHAR = 3

def limit_combining_marks(text: str) -> str:
    """限制每个 base 字符后面允许的组合标记数量"""
    result = []
    marks_since_base = 0
    for c in text:
        cat = unicodedata.category(c)
        if cat in ('Mn', 'Mc'):
            marks_since_base += 1
            if marks_since_base <= MAX_COMBINING_MARKS_PER_CHAR:
                result.append(c)
        else:
            marks_since_base = 0
            result.append(c)
    return ''.join(result)
```

### 6.4 Rust 实现推荐

```rust
use unicode_normalization::UnicodeNormalization;

/// 完备的 handoff 字符串规范化
///
/// 1. NFC 规范化
/// 2. 剥离所有 Unicode 格式字符 (General Category Cf)
pub fn normalize_handoff(text: &str) -> String {
    text.nfc()
        .filter(|c| !c.is_other_format())     // 剥离 Cf 类别
        .collect()
}

## 2. 隐蔽性分析

### 2.1 人类肉眼可见性

在终端渲染环境中，零宽字符可能显示为不可见或点状伪影（取决于终端和字体）。但在以下环境中，它们是**完全不可见的**：

- 浏览器 DOM 渲染
- GUI 文本编辑器（VS Code 默认字体）
- IDE 中的代码视图
- Markdown 预览
- Agent handoff 文档的视觉呈现

**结论**：人类读者**无法**区分原始文本 `AUTH_TOKEN_hf_abc12345` 和携带 payload 的文本。攻击的隐蔽性极高。

## 3. Payload 编码密度

### 3.1 当前编码方案（二进制）

- 使用 2 种零宽字符 (U+200B, U+200D)
- 每零宽字符携带 1 bit 信息
- 168 零宽字符 → 21 字节 payload
- **密度**: 1 bit/zw-char, 0.125 字节/zw-char

### 3.2 攻击者可选择的更高密度方案

| 编码基数 | 可用字符数 | 每字符比特数 | 编码 21 字节所需字符数 | 膨胀比 |
|----------|-----------|-------------|---------------------|--------|
| 二进制 (当前) | 2 | 1.0 bit | 168 | 8:1 |
| 已知零宽字符 | 9 | 3.17 bit | 53 | 2.5:1 |
| 全部 Cf 类别字符 | 170 | 7.4 bit | 23 | 1.1:1 |
| Tag 块 (U+E0020-U+E007E) | 95 | 6.6 bit | 26 | 1.2:1 |

**关键发现**：使用全部 170 个 Unicode 格式字符，攻击者可以将 payload 膨胀比降低到接近 1:1——即每个可见字符携带接近 1 字节的隐藏数据，同时保持完全不可见。

## 4. 修复方案完备性分析

### 4.1 normalize_handoff_fixed() 的 regex 覆盖范围

修复版本使用的正则表达式：
```python
r'[​-‏
-‮⁠-⁩﻿￰-￻]'
```

覆盖的 Unicode 范围：
- U+200B~U+200F: 零宽空格/连接符/非连接符 + LRM/RLM (5 个字符)
- U+2028~U+202E: 行分隔符/段分隔符 + 方向嵌入/覆盖/POP (7 个字符)
- U+2060~U+2069: 词连接符 + 不可见数学运算符 + 方向隔离符 (10 个字符)
- U+FEFF: BOM/零宽不断空格 (1 个字符)
- U+FFF0~U+FFFB: 行间注释锚点/分隔符/终止符 (4 个字符，含 3 个 Cf)

**总覆盖**: 23/170 个 Unicode Format (Cf) 类别字符

### 4.2 未覆盖的高危字符

| 码点 | 名称 | 威胁级别 | 说明 |
|------|------|----------|------|
| U+00AD | SOFT HYPHEN | **高** | 不可见断字符，在绝大多数渲染中不显示 |
| U+061C | ARABIC LETTER MARK | **高** | 不可见格式化，RTL 攻击面 |
| U+180E | MONGOLIAN VOWEL SEPARATOR | **中** | 历史上为零宽字符，现今为格式字符 |
| U+206A~U+206F | 对称交换/数字形状控制 | **中** | 已弃用但可能仍存在于遗留数据 |
| U+E0001 | LANGUAGE TAG | **高** | 标签序列起始，完全不可见 |
| U+E0020~U+E007E | TAG 字符 (95 个) | **极高** | 每个都是不可见的 ASCII 编码字符，可组成字符串 |
| U+E007F | CANCEL TAG | **高** | 标签序列终止 |

**Tag 块特别危险**：U+E0001~U+E007F 可以构造完整的不可见 ASCII 字符串。`U+E0001 U+E0048 U+E0045 U+E004C U+E004C U+E004F U+E007F` 在视觉上完全不可见，但解码后为 "HELLO"。

### 4.3 更完备的修复建议

**推荐方案：剥离所有 Unicode 格式字符 (General Category = Cf)**

```python
import unicodedata

def normalize_handoff_robust(text: str) -> str:
    """完备的 handoff 规范化：NFC + 剥离所有格式字符"""
    text = unicodedata.normalize('NFC', text)
    # 剥离所有 Unicode General Category 为 'Cf' 的格式字符
    # 这包括所有零宽字符、方向控制字符、标签字符等
    return ''.join(c for c in text if unicodedata.category(c) != 'Cf')
```

**验证**：
- 输入: 190 字符的中毒字符串 (含 168 个 Cf 字符)
- 输出: 22 字符的原始 token
- 提取 payload: None (payload 完全被清除)

## 5. NFC 规范化攻击面

### 5.1 字节表示变化

NFC 规范化会将分解形式组合为预组合形式，可视化不变但字节表示改变：

| 字符 | NFD 形式 (输入) | NFC 形式 (输出) | 字节变化 |
|------|----------------|-----------------|---------|
| é | U+0065 U+0301 (2 字符, 3 字节) | U+00E9 (1 字符, 2 字节) | 3→2 |
| ñ | U+006E U+0303 (2 字符, 3 字节) | U+00F1 (1 字符, 2 字节) | 3→2 |
| ü | U+0075 U+0308 (2 字符, 3 字节) | U+00FC (1 字符, 2 字节) | 3→2 |
| パ | U+30CF U+309A (2 字符, 6 字节) | U+30D1 (1 字符, 3 字节) | 6→3 |

### 5.2 攻击含义

1. **NFD 绕过检查**：如果下游组件在 `normalize_handoff()` 之前进行字符串比较，NFD 形式的字符串（视觉相同但字节不同）可以绕过允许列表检查。
2. **意外等价**：某些 Unicode 字符 NFC 规范化后与敏感关键词等效，可能被滥用。
3. **长度爆炸**：NFD 形式可能包含大量组合字符（每个 base 字符可以有多个组合标记），导致规范化后显著缩短。

**PoC 确认**：spec 正确应用了 NFC，但任何在 NFC 规范化之前的字符串比较都是脆弱的。

## 6. Rust 实现建议

### 6.1 当前项目中的风险点

MtAgentLens 的 `collector/` (Rust) 和 `frontend/` (TypeScript) 中，任何处理 agent handoff 数据的组件都可能受影响。需要检查的点：

- `collector/src/framework/analyzers/` 中的字符串处理逻辑
- `collector/src/accountability/` 中的 identity/claims 字符串匹配
- 前端中的 Markdown 渲染和 handoff 数据显示

### 6.2 Rust 实现方案

```rust
use unicode_normalization::UnicodeNormalization;
use unicode_categories::UnicodeCategories;

/// 完备的 handoff 字符串规范化
///
/// 1. NFC 规范化（与 Python 的 unicodedata.normalize('NFC', text) 等效）
/// 2. 剥离所有 Unicode 格式字符 (General Category Cf)
///    包括：零宽字符、方向控制、标签字符、BOM 等
pub fn normalize_handoff(text: &str) -> String {
    text
        .nfc()                                    // NFC 规范化
        .filter(|c| !c.is_other_format())         // 剥离 Cf 类别字符
        .collect()
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn test_strips_zero_width_chars() {
        let poisoned = "A\u{200b}\u{200d}UTH_TOKEN";
        let cleaned = normalize_handoff(poisoned);
        assert_eq!(cleaned, "AUTH_TOKEN");
    }

    #[test]
    fn test_nfc_normalization() {
        // e + combining acute accent -> é
        let nfd = "e\u{0301}";
        let normalized = normalize_handoff(nfd);
        assert_eq!(normalized, "\u{00e9}"); // é
    }

    #[test]
    fn test_no_visible_impact_on_clean_text() {
        let clean = "Hello, World! 123";
        assert_eq!(normalize_handoff(clean), clean);
    }
}
```

所需依赖 (`Cargo.toml`)：
```toml
[dependencies]
unicode-normalization = "0.1"
unicode-categories = "0.1"
```

### 6.3 使用 regex crate 的替代方案

如果偏好 regex (与 Python 版本更接近)：

```rust
use regex::Regex;
use unicode_normalization::UnicodeNormalization;
use once_cell::sync::Lazy;

static CF_STRIPPER: Lazy<Regex> = Lazy::new(|| {
    Regex::new(r"\p{General_Category=Format}").unwrap()
});

pub fn normalize_handoff_regex(text: &str) -> String {
    let nfc: String = text.nfc().collect();
    CF_STRIPPER.replace_all(&nfc, "").to_string()
}
```

Rust `regex` crate 完全支持 `\p{General_Category=Format}` 或简写 `\p{Cf}`。

### 6.4 Mojo/C 实现建议

- **C**: 使用 ICU4C 库的 `unorm2_normalize()` (NFC) + `u_charType()` 过滤 `U_FORMAT_CHAR`。
- **Mojo**: 当前 Mojo 生态中 Unicode 支持有限。建议：
  1. 调用宿主系统 Python 的 `unicodedata` (与 PoC 相同方案)
  2. 嵌入 ICU 绑定
  3. 使用预编译的 Cf 字符移除查找表

Demonstrates that normalize_handoff() from the I18n Handoff Encoding Specification

ZERO_WIDTH_CHARS = {
    "U+200B": "​",  # Zero Width Space
    "U+200C": "‌",  # Zero Width Non-Joiner
    "U+200D": "‍",  # Zero Width Joiner
    "U+FEFF": "﻿",  # Byte Order Mark (also acts as ZWNBSP)
    "U+2060": "⁠",  # Word Joiner
    "U+2061": "⁡",  # Function Application
    "U+2062": "⁢",  # Invisible Times
    "U+2063": "⁣",  # Invisible Separator
    "U+2064": "⁤",  # Invisible Plus
}

def hide_payload(visible: str, payload: str) -> str:
    """
    Embed a hidden payload inside a visible string using zero-width characters.

    Encoding scheme: each byte of the payload is encoded as 8 bits,
    each bit represented by one of two zero-width characters (0→U+200B, 1→U+200D).
    The encoded payload is inserted after the first character of the visible string.

    This makes the hidden payload completely invisible to humans while surviving
    the spec's normalization.
    """
    # Encode payload bytes into zero-width bits
    encoded_bits = []
    for byte in payload.encode("utf-8"):
        for i in range(7, -1, -1):
            bit = (byte >> i) & 1
            encoded_bits.append("‍" if bit else "​")

    encoded = "".join(encoded_bits)

    # Insert after first character so visible text looks normal
    return visible[0] + encoded + visible[1:]


def extract_payload(hidden_text: str) -> str | None:
    """
    Extract a hidden payload encoded with zero-width characters.

    Returns None if no hidden payload is found.
    """
    # Collect all zero-width characters in order
    zw_chars = [c for c in hidden_text if c in ZERO_WIDTH_CHARS.values()]

    if not zw_chars:
        return None

    # Decode bits back to bytes
    bits = []
    for c in zw_chars:
        if c == "​":
            bits.append(0)
        elif c == "‍":
            bits.append(1)
        elif c in ("‌", "﻿", "⁠", "⁡", "⁢", "⁣", "⁤"):
            bits.append(0)  # treat other zero-width chars as neutral/filler

    # Group into bytes
    bytes_list = []
    for i in range(0, len(bits) - 7, 8):
        byte_val = 0
        for j in range(8):
            byte_val = (byte_val << 1) | bits[i + j]
        bytes_list.append(byte_val)

    if not bytes_list:
        return None

    try:
        return bytes(bytes_list).decode("utf-8")
    except UnicodeDecodeError:
        return repr(bytes(bytes_list))

            "ﬁ",           # ﬁ ligature
            "fi",
        ),
        (
            "Kana: パ vs パ",
            "パ",     # ハ + combining handakuten
            "パ",           # パ (precomposed)
        ),
    ]

    for name, nfd, nfc in cases:
        nfc_result = unicodedata.normalize("NFC", nfd)
        is_nfc_equal = nfc_result == nfc

        nfc_len = len(nfc_result)
        nfd_len = len(nfd)
        spec_normalized = normalize_handoff_vulnerable(nfd)

        print(f"\n  [{name}]")

        print(f"    NFC normalized:         {nfc_result!r}")
        print(f"    NFC correct?            {is_nfc_equal}")
        print(f"    After spec normalize(): {spec_normalized!r}")
        print(f"    Spec produces NFC?      {spec_is_nfc}")

        # Security implication: 2 strings that look identical but have
        # different byte representations
        if nfd_len != nfc_len:
            print(f"    *** BYTE LENGTH DIFFERENCE: {nfd_len} vs {nfc_len} —")
            print(f"        strings are visually identical but bytes differ")


def demo_nfc_collision_attack():
    """
    Demonstrate a collision attack using NFC normalization.
    A whitelist check on the raw bytes can be bypassed if the attacker
    uses NFD form, because normalize_handoff converts to NFC —
    so an NFD string that normalizes to a whitelisted token passes.
    """
    print("\n" + "=" * 72)
    print("NFC COLLISION ATTACK")
    print("=" * 72)

    # Suppose there's a whitelist of allowed tokens
    whitelist = {"admin", "token_abc", "safe_endpoint"}

    # Attacker submits an NFD variant of "admin"
    # a + combining macron = ā, but visually similar
    nfd_admin = "àdministrator"  # a + grave accent — not quite

    # More realistic: homoglyph + NFC normalization
    # "admin" but with a combining character that NFC-normalizes to "admin"
    # Actually, NFC is a *composition* — so decomposed forms get composed.
    # The attack is: use a character that NFC-normalizes to a whitelisted word.

    # Example: NFD form of "token" — NFC normalizes to "token"
    nfd_token = "tóken"  # t + o + combining acute + k + e + n
    nfc_token = unicodedata.normalize("NFC", nfd_token)

    print(f"  Attacker input (NFD):  {nfd_token!r}")
    print(f"  After NFC normalize:   {nfc_token!r}")
    print(f"  Looks like 'token'?    {nfc_token == 'token'}")
    print(f"  In whitelist?          {nfc_token in whitelist}")

    # Actually "token" has no combining chars normally.
    # Let's be more precise: NFD of "tóken" (t + ó + k + e + n)
    t_acute_nfd = "tóken"  # o + combining acute → ó after NFC
    print(f"\n  Realistic attack:")
    print(f"  NFD input:             {t_acute_nfd!r}")
    print(f"  NFC output:            {unicodedata.normalize('NFC', t_acute_nfd)!r}")
    print(f"  Length change:         {len(t_acute_nfd)} → {len(unicodedata.normalize('NFC', t_acute_nfd))}")

    # The key insight: NFC normalization changes byte representation
    # but the spec's normalize_handoff() applies NFC, which is correct.
    # The real issue is if a downstream component does a raw string
    # comparison BEFORE the spec processes it.
    print(f"\n  Risk: If a downstream component compares strings BEFORE")
    print(f"  normalize_handoff() is called, NFD form bypasses the check.")

"""
Phase 1: Handoff Unicode Homoglyph & Zero-Width Attack Detector

Implements the normalize_handoff() function per spec, then tests it against:
  1. Cyrillic homoglyph attacks (forging tokens with lookalike chars)
  2. Zero-width character hidden payloads

Reports which attacks are DETECTED vs BYPASSED.

import unicodedata

# ─────────────────────────────────────────────────
# Part A: Spec-compliant normalize_handoff()
# ─────────────────────────────────────────────────

def normalize_handoff(text: str) -> str:
    """Per-spec implementation (Section 'Normalization Procedure')."""
    # NFC normalization
    text = unicodedata.normalize('NFC', text)
    # Strip bidirectional control characters
    text = text.replace('‮', '').replace('‭', '')
    return text

    'U+2064': 'INVISIBLE PLUS',
}

CONTROL_CHARS = set(chr(c) for c in range(0x0000, 0x0020)) | \
                set(chr(c) for c in range(0x007f, 0x00a0))


def has_homoglyph(text: str) -> list:
    """Scan text for known homoglyph characters; return list of (position, char, looks_like)."""
    found = []
    for i, ch in enumerate(text):
        if ch in HOMOGLYPH_MAP:
            found.append((i, repr(ch), HOMOGLYPH_MAP[ch], f'U+{ord(ch):04X}'))
    return found


def has_zero_width(text: str) -> list:
    """Scan text for zero-width / invisible characters."""
    found = []
    for i, ch in enumerate(text):
        cp = ord(ch)
        if cp in [0x200B, 0x200C, 0x200D, 0xFEFF, 0x200E, 0x200F,
                  0x2060, 0x2061, 0x2062, 0x2063, 0x2064]:
            found.append((i, repr(ch), f'U+{cp:04X}'))
    return found


def has_forbidden_control(text: str) -> list:
    """Check for control chars that MUST be escaped per spec."""
    found = []
    for i, ch in enumerate(text):
        if ch in CONTROL_CHARS:
            found.append((i, repr(ch), f'U+{ord(ch):04X}'))
    return found

    """Replace Latin 'e' with Cyrillic 'е' to forge a lookalike token."""
    return original.replace('e', 'е').replace('E', 'Ε')

    """Check if homoglyph-forged token patterns exist."""
    alerts = []
    for pattern in TOKEN_PATTERNS:

        forged = forge_token(pattern)
        if forged in text:
            alerts.append(f"  ⚠  FORGED TOKEN pattern detected: '{pattern}' → '{forged}'")
    return alerts

def run_test(name: str, payload: str, is_attack: bool) -> dict:
    """Run normalize_handoff on payload and audit results."""
    original = payload
    result = normalize_handoff(payload)

    homo = has_homoglyph(result)
    zw = has_zero_width(result)
    ctrl = has_forbidden_control(result)
    forged = scan_for_forged_tokens(result)

    # Did normalization actually stop the attack?
    attack_stopped = False
    if is_attack:
        # Attack is "stopped" if:
        # 1. Homoglyphs were removed (they aren't, per spec) AND
        # 2. The token pattern no longer appears as forged
        remaining_forged = scan_for_forged_tokens(result)
        if not remaining_forged:
            attack_stopped = True
        # Also check if the result is plainly safe
        if not homo and not forged:
            attack_stopped = True

    verdict = "DETECTED (bypassed normalization)" if (is_attack and not attack_stopped) else \
              ( "DETECTED (mitigated)" if (is_attack and attack_stopped) else "CLEAN" )
