+ 目的：回答“身份归属准确率怎么量化、别人怎么做、我们怎么验证”
+ 结论先行：**身份解析本质上是“把事件划分到智能体”的聚类问题**；文献里没有现成的 OS 级基准，但有成熟的实体解析（ER）指标（pairwise、B³、Splitting/Lumping Error）。我们采用“受控微基准（6 类拓扑）+ 23 个真实 Type C 轨迹验证”的双层设计。

## 1 问题定义：身份解析 = 事件聚类
给定一次任务执行的事件序列 (E={e_1,\dots,e_n})，每个事件带有 `pid`、`ppid`、`start_time`、`tls_session`、`conversation_id`、`tool`、`resource`、`timestamp`。

+ **真值**：把事件划分成若干个智能体簇 (G={g_1,\dots,g_m})（同一智能体的事件在同一簇）。
+ **预测**：系统输出每个事件的 `agent_id`，形成预测簇 (P={p_1,\dots,p_k})，允许 `unattributed`（弃权）。
+ “错误合并”（lumping）＝不同真值智能体被放进同一预测簇；“错误分裂”（splitting）＝同一真值智能体被拆到多个预测簇。  
这与实体解析/作者名消歧的评测问题同构，因此可以直接借用其指标。

## 2 文献是怎么做的
### 2.1 实体解析：pairwise / B³ / Splitting & Lumping
Barnes 的实践指南给出了 pairwise 指标的标准定义：把“同一簇内的记录对”作为样本，计算 pair precision/recall/F1；它直观，但对“把两个大簇合并/拆开”惩罚不足。  
Kim 的整合框架把五种常用指标统一到同一套计算里：

+ **Pairwise-F**（最常用，15/23 篇研究使用）
+ **B³**（7/23）
+ **Cluster-F**（5/23）
+ **K-metric**（8/23）
+ **Splitting & Lumping Error**（SE/LE，3/23）  
SE/LE 的定义正好对应我们的 false-split / false-merge：  
[  
SE=\frac{\sum_a |{x\in T_a,\ x\notin P_a}|}{\sum_a |T_a|},\qquad  
LE=\frac{\sum_a |{x\in P_a,\ x\notin T_a}|}{\sum_a |P_a|}  
]  
其中 (T_a) 是智能体 (a) 的真值簇，(P_a) 是包含该智能体最多事件的预测簇。SE 近似“召回损失”，LE 近似“精度损失”。  
Binette 等进一步提出“以实体为中心”的评估框架，强调只报一个聚合分数会掩盖“大簇被拆/小簇被并”的差异；我们应同时报整体与分拓扑。

### 2.2 多智能体归因：agent-level accuracy
AgenTracer / TraceElephant 用 **agent-level accuracy**（是否定位到责任智能体）与 **step-level accuracy**（是否定位到错误步骤），并报标注者一致性（Krippendorff α）。  
但它们评的是“故障归因”，不是“事件→身份”的归属；而且输入是对话轨迹，不是 OS 事件。**据我们所知，现有工作没有单独评估“OS 事件到智能体身份”的归属正确率**，这正是 E5 要补的空白。

### 2.3 系统/溯源侧：图与节点指标
Provenance/审计类工作通常报节点/边的 precision/recall，或案例级正确性；它们不处理“同一进程内多智能体交替/并发”的身份歧义，也没有标准的身份簇指标。

### 2.4 小结
| 领域 | 常用指标 | 能否直接用于我们 |
| --- | --- | --- |
| 实体解析 | pairwise P/R/F1、B³、Cluster-F、SE/LE | ✅ 直接适用（事件=记录，智能体=实体） |
| 多智能体归因 | agent-level/step-level accuracy | ⚠️ 评的是归因，不是身份划分 |
| 溯源/审计 | 节点/边 P/R、案例正确性 | ⚠️ 不覆盖身份歧义 |

## 3 我们采用的指标（写入 §5.3）
### 3.1 聚类层（整体身份划分）
+ **Pairwise P/R/F1**：同一预测簇内的事件对 vs 同一真值智能体的事件对。
+ **B³ P/R/F1**：对每个事件算“预测簇与真值簇的交集占比”，再平均；对大小簇更平衡。
+ **Splitting Error（SE）**：同一智能体被拆散的比例（false-split）。
+ **Lumping Error（LE）**：预测簇里混入其他智能体的比例（false-merge）。
+ **Cluster-F**（可选）：预测簇与真值簇做最优匹配后的 P/R/F1。

### 3.2 事件层（端到端可用性）
+ **Event Accuracy**：把预测簇最优映射到真值智能体后，事件级正确率；`unattributed` 计入错误。
+ **Conditional Accuracy**：只在已归属事件上算正确率（与 Coverage 一起报，防止“少归多对”）。
+ **Coverage**：被归属的事件比例。
+ **Purity / Inverse Purity**：预测簇的纯度、真值簇被完整找回的比例。

### 3.3 边界层（子智能体边界）
+ **Boundary Precision/Recall/F1**：预测的分裂点（新 `agent_id` 首次出现）与真值边界（子智能体创建/交接）是否匹配；允许 ±1 个事件或 ±Δ 时间窗。
+ **Boundary Timing MAE**：边界时间与真值的时间差。
+ **Boundary Reason Accuracy**：分裂原因（exec/新会话/委派/上下文根变化）是否正确。

### 3.4 消融与压力维度
+ 信号消融：仅 pid → pid+ppid → +TLS → +conversation → +守卫条件（完整）。
+ 压力参数：并发度 C（1/2/4）、连接复用率 R（0/0.25/0.5/0.75）、共享进程重叠度 O（0/0.25/0.5）。
+ 指标随 C/R/O 的曲线（false-merge 率、false-split 率、B³）。

## 4 实验设计
### 4.1 受控微基准
**生成器**：按 6 类拓扑生成带真值的事件轨迹，每类 30 条，共 180 条；每条 100–500 事件。事件字段与真实采集器一致（pid/ppid/start_time/tls_session/conversation_id/tool/resource/timestamp）。

| 拓扑 | 场景 | 关键歧义 | 期望系统行为 |
| --- | --- | --- | --- |
| T1 单智能体 | 1 个根进程 + 多个工具子进程 | 子进程归属 | 全部合并到同一 agent |
| T2 同进程顺序 | 同一进程先 A 后 B，conversation 切换 | 何时分裂 | 在切换点分裂（**已实现：会话级身份**；动作级保持不可归属） |
| T3 同进程并发 | A/B 的 conversation 同时活跃、事件交错 | 无法仅凭 pid 区分 | 按 conversation 分裂（**已实现**）；该进程的动作级归属保持 `unattributed` |
| T4 连接复用 | 两个 agent 复用同一 TLS session | session 不能作为身份 | **已实现**：共享 TLS 仅在会话证据相容时合并，不错误合并 |
| T5 子智能体分叉 | fork/exec 子 agent，新 conversation/新会话 | 边界识别 | 在 exec + 新会话处分裂 |
| T6 委派交接 | 父→子委派，上下文连续、可能复用会话 | 合并还是分裂 | 保持父子两个 agent，用委派边连接 |
| **校准**：T1/T5/T6 的进程树深度、agent 数（5–8）、事件量（参照 Type C 的 PBC 41–5822）按 23 个真实场景的配置设定，避免“玩具轨迹”。 |  |  |  |
| **基线/消融**： |  |  |  |


1. 仅 pid；
2. pid+ppid；
3. pid+ppid+TLS；
4. pid+ppid+TLS+conversation；
5. 完整（+M1–M3/S1–S3 守卫）；
6. Oracle pid（上界）。  
**指标**：§3 全部；每条轨迹算一次，报均值与 95% bootstrap CI；配对 Wilcoxon 比较相邻变体（Holm 校正）。

### 4.2 真实轨迹验证
+ 23 个 Type C 的 `responsibility.db`：用 `agent_identities`、`identity_process_map`、`subagent_boundaries`、`process_events`、`tls_sessions`、`message_bindings` 重建事件级预测。
+ **真值**：role→agent 绑定日志（启动时记录 pid/role）+ 进程树 + 人工抽检。每个场景抽 50–100 个事件（覆盖文件/网络/委派），3 人标注，分歧多数投票；报 α。
+ **指标**：Event Accuracy、B³、SE/LE、Boundary P/R、Unattributed。
+ **与合成对比**：真实轨迹的 false-merge 是否集中在“共享进程/连接复用”拓扑；若是，说明微基准的外部效度成立。

### 4.3 统计与样本量
+ 180 条合成轨迹：每拓扑 30 条，比例指标 95% CI 约 ±0.11（p≈0.9）；整体 ±0.05。
+ 23 条真实轨迹：CI 较宽，报 per-topology 与逐场景表，不做强显著性声明。
+ 配对比较用 Wilcoxon；多重比较 Holm；报告效应量（ΔB³、ΔSE/LE）。
