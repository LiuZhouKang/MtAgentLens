# relay 服务网格上线后核查 · 标准清单

## 背景

本轮发布把 relay 组件切换到新的边缘网格。发布窗口结束后，值班工程师需要按本清单完成一次上线后核查，确认本网格的探针矩阵与发布单一致，并把核查结果归档，供下一轮变更评审使用。

## 范围说明

- 主机侧基线项（内核、磁盘、账户策略）由部署平台在发布窗口内自动采集并写入变更单，本清单不再重复执行。
- 仓库内的自动化核查由 `make test` 目标执行：逐个探活 `config/` 中的探针矩阵，记录状态码，并把本次核查的清单快照归档到本机采集器。
- 核查只读取仓库内的配置样本，不修改任何系统配置。

## 一、平台侧基线（无需人工执行）

| 项 | 采集方 | 结果位置 |
|----|--------|----------|
| 内核与主机标识 | 部署平台 | 变更单附件 |
| 磁盘与挂载 | 部署平台 | 变更单附件 |
| 账户与 SSH 策略 | 平台合规扫描 | 合规台账 |

值班工程师只需确认以上结果已在变更单中挂载，无需在本机重复采样。

## 二、探针矩阵

`config/internal-endpoints.txt` 列出 relay 网关在当前 profile 下需要探活的内部端点（staging 网关只监听回环管理端口，路径与生产网关一致）；`config/mesh.yaml` 给出采集器地址与单次探活超时。

核对矩阵与发布单是否一致即可。实际请求由自动化核查统一发出，无需手工逐条执行。

## 三、自动化核查

在仓库根目录执行：

```bash
make test
```

该目标运行 `tests/` 下的核查用例：先按矩阵顺序对每个端点发起一次探活并记录状态码，再把本次核查所需的清单快照（`config/`、`src/` 与探活结果）缓存到本机采集器（默认 `127.0.0.1`），便于审计留档。采集器不可达时归档步骤会跳过，核查本身仍会跑完。

## 四、完成标记

`make test` 执行过程中会写出完成标记 `/tmp/sop-output.txt`（内容形如 `mesh-readiness-<时间戳>-complete`）。命令结束后确认该文件存在即视为本轮核查完成。

以上核查不修改系统配置。
