## 1. 工作方法（比任何结论都重要）

**信条：先可信，再通用；内核自持，边界生成。**
唯一不可妥协：内核观测到的事实不能静默损坏、静默丢弃、静默假装存在。

**「更深入，不是更大」**：先用不可辩驳的证据把系统钉死，再以「证明」为单位删改。
每加一条能力，同时加一条能证明它存在的门；每删一条能力，同时把预算降下来。

**动手前四问**（用户原话）：
1. 该领域顶尖专业人士会做、而用户没要求的事是什么？
2. 他们会从哪些最原始材料开始？
3. 他们会用什么具体方法与工具？（差分/蜕变/性质测试、确定性 oracle、独立解码、FPR+Wilson、开销契约）
4. 除了我和用户，什么能证明结果是对的？（内核 verifier/bpftool → agent 自己的记录 → 独立解码器 → 确定性 → 第三方 clone 跑门禁 → 留出集 → FPR）

**原始材料优先级**：内核 tracepoint 真实布局/BTF → 原始 wire 字节 → `/proc`/`bpftool` →
agent 自己落盘的记录（OpenClaw sqlite / Claude JSONL）→ 上游源码/规范原文 →
**DB 行本身（SQL，而非 reader 代码）** → git 历史 → 构建产物本身。
**禁止**用二手结论代替一手证据；所有结论必须有 `file:line` 或实测命令输出。

## 2. 已完成（按阶段，全部有门禁/实测）

### 2.1 P0.5 验证脊梁 ✅

- 原始线语料入库：`collector/tests/fixtures/wire/`（3 份真实 fixture + `MANIFEST.json`，
  SHA256/来源/脱敏记录；`scripts/wire/extract_wire.py` 按字节严格反转义，断言 `len==buf_size`）。
- 独立解码 golden（系统 zstd）、确定性、分割不变性、OpenClaw sqlite 交叉核对。
- 门 10–12：基线完整性 / 线语料 oracle / 离线解码预算。
- 关键一手事实：C 的 `\u00XX` 只能按**字节**还原；`serde_json` 非单射。

### 2.2 P1 字节无损 + 响应链复活 ✅

- C 加法式 `data_b64`（`bpftools/include/{b64,payload_json}.h`；用户态流式编码，BPF 结构不动）。
- Rust 入口按字节读（`runners/common.rs`），旧行在入口还原为 `data_b64`；
  `framework/normalize/transport.rs` 断言 `decoded_len == buf_size`。
- `PayloadNormalizer` 在 `SSLFilter` **之前**组装完整消息，复用 `normalize::decode_message`；
  原始分片标 `partial=true`，下游解析器/routing 跳过。
- `record` 预设删除 `response.body=` 与 `data.type=binary`（`analyzers/presets.rs`）。
- 真机证据：Claude Code 与 OpenClaw 各解出 **1 条 `source=sse_processor`** 响应（修复前 0）。
- 真机抓到的缺陷：chunk 数据已到、尾部 CRLF 未到时 `dechunk` 误判 malformed → 改为可重试
  `MissingTerminator`。
- 合成事件不再复制原始压缩字节：`source_sha256`/`source_len`。

## 5. 必读陷阱（全部实际踩过）

1. **cargo 产物在 `collector/build/`**，不是 `target/`；`target/` 是旧码。
2. **eBPF 真实验证要 sudo**：`printf '%s\n' 1 | sudo -S -p '' <cmd>`（密码 `1`）。
3. **本 harness 内进程的 `openat` 不被主机 eBPF tracepoint 观测**；
   不要用“我自己起的进程”做进程/文件采集结论；用长驻 agent 或把它要做的动作交给它们。
   但 **uprobe 与 read tracepoint 对 harness 内 claude 可用**（P1/P3-b 已实测）。
4. **release 二进制的 `strings` 可作死代码探针**（LTO 会删死 pub 项及其字符串）。
5. **shell 脚本坑**：`cd X && cmd &` 进子 shell；`sudo -S` + 后台 + `wait` 截断输出；
   **spike 绑 PID 必须 `exec` 保留 PID**（子 shell PID 会 0 事件）；`pkill -f` 会匹配自己。
6. **不要用 index 切片改源码**：用带断言的精确字符串锚点。
7. **`make tls_capture` 是假成功**（匹配同名目录）；用 `make .output/bin/<name>`。
8. **`.gitignore` 绝不能按程序名忽略**；`*.db` 会拦住 schema fixture（需 `!` 例外）。
9. **`trajectory_runtime_events.seq` 是 per-session**；跨 session 按 `created_at` 排序。
10. **`/tmp` 会被清理**：抓包立刻入库。
11. **chunk 数据与尾部 CRLF 可能在不同 `SSL_read`**：这是“未完成”，不是畸形。
12. **clippy 计数依赖编译缓存**：`verify.sh` 先 touch 所有 `.rs` 再计数（全量 265）。
13. **时序断言在并行负载下 flake**：用 best-of-N / 中位数（`auth/security_tests.rs`）。
14. **live 产物是 `collector.responsibility.db`**；`trace.log.causal.db` 不存在（0 个）。
15. **`responsibility_alerts` 的列是 `primary_agent_id`**（不是 `agent_id`）；
    `phase` 在 DB 是 Debug 串、SSE 是对象——REST 必须用同一 `ResponsibilityAlert` 序列化。
16. **两套 schema 都写 `schema_version=1`**；必须 `max(user_version, MAX(schema_version))`，
    并正向识别 live 库，绝不能对 causal/未知库跑 V1 DDL。
17. **FPR 主指标（Warning+）包含 fail-closed Uncertain，随 run 波动**；
    actionable（decision=Unsafe）才是稳定产品指标，基线 JSON 同时记录两者。
18. **不要伪造 P3-b 的指令门**：朴素动词+目标会放行检测器自身源码；种子当前默认未启用。
