# 身份解析、责任链溯源与根因定位：实验设计及论文写作依据

> 核对日期：2026-10-29。本文档整合仓库中的实验报告、数据卡、生成器和评分实现，服务论文方法、结果与局限性写作。状态分为 **已执行并有报告**、**指标已实现**、**方案/待完成**。论文中的正式数值仍须绑定对应冻结构建、输入及可访问的结果产物；本次文档整理未重跑实验。

## 2. 评价对象与术语

一次运行包含可观测事件集合。身份解析把事件组织成主体簇；责任图把具有证据支持的事件或实体关系组织成图；根因定位从证据中提出可能的来源主体和入口。这三层相互依赖，但评价问题不同：

1. **身份归属**：哪些事件属于同一逻辑智能体？可观测信号不足时是否保留未知？
2. **链路溯源**：预测的事件间有向关系是否与独立参考一致、是否覆盖参考边？
3. **根因定位**：提出的来源主体、关键步骤和入口是否与参考一致？
4. **因果验证**：移除候选原因或切断路径是否改变结果？这需要干预，不能从前三层自动推出。

进程身份由 PID 与内核启动时间组合表示，避免 PID 重用混淆。TLS 参与关系与 conversation 是归属提示而非经过认证的智能体身份；显式委派和不相交会话提供分离约束。共享进程内，带会话标识的消息可按 `(process, conversation)` 区分；缺少会话标识的动作不能仅凭进程强行指定给其中一个逻辑智能体。参见 [论文替换稿](revision-package.md)。

“根因”需在实验前通过 codebook 明确定义为有证据支持的源头或贡献主体，并区分最早入口、直接执行者和关键步骤。纯观测支持的是证据约束的归因，不自动证明该主体对结果具有反事实必要性。多根、证据不足、良性不存在攻击根因均需有不同编码，不可一律用空值处理。

## 3. 已执行：E5 合成身份微基准

### 3.1 目的、输入与真值

E5 是离线规则规格测试：以进程树、TLS 参与者、conversation 和明确委派构造合成信号图，调用真实 `IdentityResolver` 的 provisional 和 authoritative 路径，再将预测分簇与事先声明的拓扑真值比较。真值来自拓扑规格，而不是系统的输出；实验不依赖模型调用或真实 eBPF 采集。

| 编号 | 输入结构 | 事先声明的预期 |
|---|---|---|
| T1 单智能体 | 一个主进程及工具子进程 | 事件属于同一主体 |
| T2 同进程顺序会话 | 一个进程先后关联两个 conversation | 以会话区分两个主体 |
| T3 同进程并发会话 | 一个进程关联两个并发会话 | 按会话分离；缺少可判别信息时应允许未知 |
| T4 连接复用 | 两个主体复用 TLS session，各有不同 conversation | 不能仅因共享连接合并 |
| T5 子智能体分叉 | 父子 agent 进程，独立 TLS 和会话 | 父子分离 |
| T6 显式委派 | 父子共享会话与连接，另有委派关系 | 父子分离，保留委派关系 |

每类 30 条，每条 4 个抽象事件，合计 180 条、720 事件；T1 只有一个真值主体，T2–T6 各有两个真值主体。30 条主要改变 PID 和时间，结构不变，不是 30 个独立真实场景或 30 次随机采样。生成器是 [identity_microbenchmark.rs](../../../collector/examples/identity_microbenchmark.rs)，评价器是 [e5_identity_microbenchmark.py](../../../scripts/evaluation/e5_identity_microbenchmark.py)。较早设计稿提出 100–500 事件、信号消融及压力曲线，**不等于本次已执行的 E5**。

特别地，T2/T3 的四个受测事件均携带 conversation；它们并未检验同一共享进程中缺少会话字段的文件或网络动作。T3 名称描述并发拓扑，但生成器使用的是构造好的信号快照，不是实际并发执行与实时调度压力测试。

### 3.2 计分方法与示例

真值和预测均表示为同一事件集合上的划分，簇标签可以任意改名。对每条轨迹内的无序事件对：

- TP：真值同主体，预测也同簇；FP：真值不同主体，预测同簇；FN：真值同主体，预测分簇。
- Pairwise P = TP / (TP + FP)，R = TP / (TP + FN)，F1 = 2TP / (2TP + FP + FN)。分母为零的量由实现返回 `None`。
- B³：对每个事件 e，设预测簇为 P(e)、真值簇为 G(e)，分别计算 `|P(e)∩G(e)|/|P(e)|` 和 `|P(e)∩G(e)|/|G(e)|`，再对事件平均，最后由平均 P、R 计算 F1。
- 错误合并簇：包含多个真值主体的预测簇数；错误分裂簇：分布在多个预测簇的真值主体数。
- 未归属率 = 未归属事件数 / 全部受测事件数；每个未归属事件在 E5 中作为独立单例参与分簇计分。

例如真值为 `{A1,A2}` 与 `{B1,B2}`，预测将四个事件合成一个簇：TP=2、FP=4、FN=0，P=1/3、R=1、F1=0.5。若每个事件都被拒绝归属，单例处理不会制造错误合并，但会损失同主体事件对召回；因此必须同时报告 F1、合并/分裂及覆盖率。

E5 按轨迹计算指标，再按拓扑对有定义的数值取算术平均；未归属率按该拓扑事件总数计算。代码中的 `wrong_merge_rate` 是错误合并预测簇数之和除以轨迹数，属于**每条轨迹平均错误合并簇数**；它不一定在一般情况下等于含错误合并的轨迹比例。不要把两者或事件错误率混称。

## 4. 真实身份实验：待实施方案

本节是基于 [IdentityBench 方案](../evaluation/EXPERIMENT-IDENTITY-ATTRIBUTION-2026-10-26.md)整理的目标协议，**不是已完成结果或现成可运行管线**。

### 4.1 样本、冻结与拓扑

计划以冻结 FuxiBench 中多 Agent 场景为研究集，目标为 30 个 multi 场景各一次运行；具体成员、可用运行、标签和最终分母必须在开跑前根据 release manifest 固定。当前数据卡记载总计 93 场景，其中 30 个多 Agent 场景；`multi_agent_attack` 分类有 23 个场景，其当前标签为 A 11、B 11、benign 1。旧 Type C 分类已退役，不要把“旧 23 Type C”直接等同于当前 23 个 B 类攻击。数据集目前报告 58 attack、35 benign，检测排除数为 0；其他旧文档关于 9 项排除的描述属于过期口径。参见 [数据卡](../../datasets/FuxiBench/DATASET-CARD.md)。

记录每个运行的 launch manifest、实际任务/输入哈希、原始事件、进程树、可用会话关联、agent 日志、采集质量、配置和构建身份。实验前普查共享进程、多会话、连接复用、并发和委派是否真的发生。某种拓扑缺失时，应报告未覆盖；受控补充样本与真实样本分表，不混成一个估计。

每场景仅一次运行只能描述所选运行，无法估计同场景运行间变异；重复运行若增加，统计重采样仍须按场景聚类。场景是有目的设计的方便样本，并非生产流量随机样本。

### 4.2 参考、分层采样与盲化

- **顶层启动锚点**：执行器记录的角色、进程及 session/pane 对应关系可作为声明级、范围有限的外部锚点；不能据此认定进程内所有逻辑子智能体或每个 OS 动作的身份。
- **运行事件参考**：冻结任务和原始轨迹，按预先定义的事件类型与拓扑抽样，覆盖边界/交接及消息、工具和 OS 动作。旧方案建议每 run 每类各 20 个加全部边界事件；这是待冻结采样方案，需记录实际可用数、抽样概率及不足情况。
- 参考制作者不看待评价系统的身份、告警、根因或预测图；保留原始证据锚点、codebook 版本、独立记录和裁决过程。证据不足明确标 unknown。若采用三次独立 AI 会话加独立裁决，名称应为 **AI 参考及与 AI 参考的一致性**，不是人工金标；同模型一致性不等于真值准确率。当前数据卡记录人工标注为 0。
- 预测 actor 与参考 actor 的语义映射须依托独立建立的锚点，不能用同一评价标签拟合映射后再宣称动作归属准确；聚类指标本身对簇名称置换不敏感。

### 4.3 条件及指标

计划对同一冻结事件集离线比较 PID-only、PID+PPID、再加 TLS、再加 conversation、再加委派与边界的完整解析；必须先实现并验证各条件可配置、输入一致、顺序确定。E5 作为受控规格测试单列；不可将其并入真实结果。

完整、唯一归属且参考和预测使用相同 run、证据包、事件集时，可用现有 [identity_metrics.py](../../tools/identity_metrics.py) 计算 pairwise 和 B³。它的完整分簇 API 不接受候选集或真实 unknown，也不在选择出的子集上自动算分；真实数据应预先定义可评分全集及处理机制，不得事后挑选。候选集/弃权使用该文件的另一套接口，分别报告参考已知数、预测覆盖率、单候选正确率、候选命中率及候选集大小；不能把候选命中当成唯一身份准确率。参考 unknown、预测 unknown、双方均 unknown 的数量分列。

应预先明确 micro 汇总（汇总事件对计数）和 macro 汇总（每 run 计分后平均）以及未定义分母处理；记录错误合并和错误分裂的**精确分子、分母**，不要混用错误簇数、事件比例与事件对比例。若只统计已回答事件的条件准确率，必须同时报告对应覆盖率与参考已知覆盖率。

## 5. 根因、入口与责任链：指标实现

当前 [root_cause_metrics.py](../../tools/root_cause_metrics.py) 使用 `mtagentlens.root-cause-metrics/2`，要求参考及预测 run ID 唯一且集合完全一致。参考的 `root_agent` 非空，预测是候选排序、入口、事件有向边和边界类型；重复候选、畸形边、图中有向环等会被拒绝。事件实例 ID 必须能区分同一 actor 的不同动作；不应直接用重复 actor ID 代替事件节点。

| 输出 | 已实现的精确计算 | 适用范围 |
|---|---|---|
| RootAgent@1 | 参考单根因位于首位的 run 比例 | 所有输入参考 run；预测空列表为 miss |
| RootAgent@3 | 参考单根因出现在前三位的 run 比例 | 仅当所有非空预测排序声明来自冻结、确定排序；否则 `None` |
| MRR | 参考单根因排名倒数的 run 均值；不在列表中为 0 | 同上；未报告不是 0 |
| EntryPoint Accuracy | 在参考入口非空的 run 中，预测与参考字符串完全相等的比例 | 参考入口空时该 run 不计入该指标；预测空为 miss |
| Chain P / R / F1 | 对参考边非空的每个 run，分别算边交集/预测边数和边交集/参考边数，再分别对 run 求均值，最后对这两个均值计算 F1 | 预测空边时 P、R 均记 0；参考空链表示未标注，跳过 |
| Chain Depth MAE | 对参考边非空的 run，求两图最长有向路径边数的绝对差，再求均值 | 预测空链深度为 0；分支和汇合取最长路径 |
| Boundary-type Accuracy | 对参考类型非空的 run，算预测与参考类型集合的 Jaccard，再求均值 | 参考空集合不计入该指标 |
| missing_root_predictions | 参考根因不在预测候选中的运行数 | 与整体 run 数一起报告 |

该链 F1 是**先对每运行 P、R 宏平均，再计算 F1**，不是所有边汇总的 micro F1，也不是逐 run F1 的均值。链边需要可验证的共同事件实例对齐，且参考与预测应采用同一边语义；顺序不影响边集合比较，有向方向本身仍是匹配的一部分。入口当前为严格字符串匹配，不提供自动的资源规范化或时间容差。

示例：三个参考根因分别在预测第 1、第 3 和缺失时，@1=1/3、@3=2/3、MRR=(1+1/3+0)/3≈0.444；这个例子仅在排序满足冻结条件时可报 @3 和 MRR。当前接口是单根参考；多根 RootSet、step、路径有效性和时间容差属于后续方案，需要明确实现及评测，不可写作现有评分器已提供。

## 6. 真实归因与溯源实验：待实施方案

### 6.1 参考与预测分离

复用与身份实验绑定的冻结运行，先依据独立证据判断攻击是否执行以及参考能否判定；`yes/no/unknown` 分开记录。场景是 attack 标签不代表本次攻击已经执行；marker 只证明钩子触达，接收端收据只支持对应载荷到达，均不能独立证明所有目标成功。

按 scope → localize 建立运行参考：标注参与主体与事件、根因主体集合或 unknown、关键步骤、首次不可信内容/交接入口、到风险动作的有向证据边，以及各字段证据引用。允许多根、分支、汇合和缺失证据；只用有证据的事件实例边，不因展示相邻或时间相近而构造因果边。根因参考依赖身份参考时，应说明依赖关系，不能把两套参考当作相互独立证据。

预测按相同单位输出主体、入口、边和弃权状态，并与参考隔离。明确区分“参考未知”“参考明确无根因”“预测弃权”“采集失败/执行未知”；先报告全 cohort 流向和各字段分母，再报告可判定子集结果。良性中的 false-root 需以**参考可判定无攻击根因**的良性运行为分母，并写明如何处置 unknown 与系统未输出。

### 6.2 对照、统计和解释

目标方案在同一证据集上比较完整方法与 alert primary agent、最后动作主体、最近意图主体等简单规则，并可评估去入口、去污点边的消融。所有方法的输入、可用信息、预测缺失处理及参数须在实验前固定；这些方法和消融目前是方案，不能声称已实现或已取得增益。根因主体、步骤和入口分别报，不能用主体命中替代步骤命中。支持多根时，先定义集合 P/R/F1 与多根排序口径并实现测试；现有单根评分器不能直接充当多根评测。

计划以场景为统计单位进行配对比较与场景级 bootstrap，预先固定主指标、置信区间、重采样次数、种子、多重比较处理和缺失策略。样本量小、非随机、每场景一次运行时，区间主要反映所选场景内的不确定性，不代表生产总体或运行间稳定性；子组分析作为探索。被评估方法共同缺少证据时也要报告，避免只在有预测的运行中比较。

可选的反事实研究需先冻结干预条件、对照和结果判据，比较移除载荷、禁用主体或切断委派前后的风险动作，保留重复次数与执行失败情况。若只观察到结果消失，也应说明随机性、替代路径及干预副作用；该研究目前不是已完成结果。

### 6.3 开跑前门槛

1. 确认冻结 release、场景成员、构建、采集配置、启动身份和输入绑定；检查采集质量与攻击执行证据。
2. 打通运行事件与外部身份锚点的可靠对齐；当前生命周期记录与 collector 事件不是天然相同全集。
3. 冻结盲化范围、codebook、参考 schema、采样、unknown 和裁决协议；实际标注者身份及方法如实记录。
4. 实现并验证身份各条件及归因预测导出、候选排序或集合、事件 DAG、相应基线与评分适配；逐项核实当前版本，不把旧审计中的缺失清单当作永恒状态。
5. 完成小规模 pilot，验证端到端事件对齐、参考覆盖、评分分母和空值语义，再冻结正式 cohort 和分析计划。
6. 未满足任一必要条件时，结果标记 pending；不把设计级 causal proposal、场景角色、模型建议或 detector 输出改称运行真值。

当前 [最终 RC 检查单](../evaluation/final-rc-checklist.md)仍指出逻辑身份和运行根因参考链路未就绪；已有运行标注路径的 `root_actor` 不能直接提供根因参考。此类状态需要在实际实施前再次核验，避免将过期实施细节当作现状。

## 7. 可直接用于论文的表述

以下是基于**当前已记录证据**的保守中文文本；数字提交前需重算或核对可访问 artifact 与构建身份。未完成实验不使用完成时态。

### 7.1 方法：身份解析与评价

> 为检验身份融合在共享进程、连接复用和委派场景中的边界行为，我们构造六类合成信号拓扑，覆盖单智能体工具子进程、同进程顺序与并发会话、TLS 连接复用、子智能体分叉及委派交接。各拓扑预先声明事件到主体的参考划分，并调用系统的身份解析器生成预测划分。每类构造 30 条轨迹，共 180 条轨迹、720 个抽象事件。我们逐轨迹比较参考与预测的同主体事件对，计算 pairwise precision、recall 和 F1，同时统计错误合并、错误分裂及未归属事件。对于未归属事件，计分时将每个事件视为独立单例，并单独报告未归属比例。

### 7.2 结果：受控拓扑

> 在上述六类受控拓扑中，修复后的记录显示各类 pairwise F1 均为 1.000，未观察到错误合并簇或错误分裂的参考主体，受测事件的未归属比例为 0%。该结果表明解析器对这些预设合并和分离规则的实现与规格一致。同进程多会话的受测事件均携带会话标识；缺少会话信息的系统动作仍可能无法唯一归属，因此上述结果不代表真实动作级或端到端身份准确率。

### 7.3 方法与局限：真实归因

> 对真实运行中的身份与根因评价，需要将冻结运行的预测与独立参考对齐。主体定位可在参考根因明确时报告 RootAgent@1；当预测存在预先冻结的确定排序时，可进一步报告 Top-k 与 MRR。入口按预定义语义比较，责任链按事件实例间有向边比较 precision、recall 和 F1，并报告参考覆盖率、预测弃权及采集质量。现阶段独立运行级身份和根因参考尚未闭环，因此本文不报告真实根因定位准确率；责任图和链深作为证据组织的案例展示，不作为正确率的替代。

如未来采用 AI 参考，应将“正确率”改为“与 AI 参考的一致性”，说明标注、裁决和参考局限；若采用人工参考，只有真实完成独立人工标注和复核、保存可审计记录后才能作相应表述。
