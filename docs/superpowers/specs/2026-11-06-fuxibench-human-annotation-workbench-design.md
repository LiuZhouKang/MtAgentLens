# FuxiBench 人工标注工作台设计

## 目标

为 FuxiBench 增加场景级标注工作台，减少逐文件编辑 JSON 的工作量，同时保留三位标注者各自独立的原始判断、证据依据和后续裁决记录。

## 范围

- 复用 `tools/annotator` 的本地工作台形态，但新增与运行级标注隔离的 FuxiBench 场景标注入口和存储格式。
- 读取现有场景输入、fixture、bench 脚本、codebook 与 GT；展示输入材料和版本/摘要信息。
- 表单按现有 codebook 字段录入 `label`、`attack_type`、`expected_behaviors`、`benign_activity`、`min_decision`、`execution_check` 与不确定项。
- 每位标注者独立保存、提交；提交前不展示其他标注者答案。提交后提供差异比较、裁决理由记录与结构化导出。
- 全部场景完成独立提交后，按适用字段报告原始一致率与 Fleiss’ κ，并注明统计来自裁决前记录。
- 提供一键载入场景、保存草稿、提交及校验全体标注的操作；自动校验只检查完整性、枚举和结构，不推断语义标签。

## 标注材料边界

场景级标注只使用场景设计材料：任务、角色、fixture、bench 脚本、相关说明和 codebook。Agent trace、collector 事件、检测输出和运行结果属于运行级证据，不用于决定场景级标签。界面需明确区分这两种标注对象，避免运行事实泄漏到场景真值。

标注结果由标注者填写和确认。标注者姓名从预设名单中选择；本地工作台不提供身份认证。

## 数据与流程

1. 管理者选择数据集、codebook 版本及标注者名单，建立标注轮次并冻结输入摘要。
2. 标注者打开自己的队列，逐场景查看材料并按 codebook 填写；可保存草稿、标记不确定并写明证据路径/片段。
3. 提交时记录标注者、时间、codebook 版本和输入摘要；提交记录不可静默覆盖，修改以新版本追加并说明理由。
4. 三人完成后，工作台按字段汇总分歧；裁决者填写最终值、理由和关联原始记录。
5. 导出独立提交、裁决结果、字段完整性报告及可复现的 CSV/JSON；只有原始独立记录可用于计算标注者一致性。

## 实现边界

优先采用仓库现有本地 Python 服务和静态 HTML 工作台，不引入新框架或外部服务。标注数据与现有 run-level evidence bundle/SQLite 分库存储，不混用其 schema。现有 FuxiBench GT 仅作为只读参考或发布目标；标注过程数据先写入独立工作区，人工确认导出后才替换正式 GT。

## 验收标准

- 可从当前 93 个场景建立标注轮次，字段与现行 codebook 对齐。
- 三位标注者可独立保存；任何未提交者看不到他人答案，提交后可比较差异。
- 全部 93 个场景完成三人提交后，可生成场景标签、攻击类型和监测裁决字段的一致性统计。
- 刷新或重启服务后草稿与提交仍在；每次修改可追溯到前版和修改理由。
- 无效枚举、缺少必填字段、行为 ID 重复或结构不完整时不能提交/发布，并指出具体字段。
- 导出包含每人原始答案、最终裁决、codebook/input 摘要；不会把运行级标签混入场景级结果。
- 通过新增的聚焦自动化测试和现有 annotator 相关测试。

## 风险与约束

本地工作台不提供强身份认证或多人远程协作安全保证；本版本面向受控本地标注。若标注者共用账号、查看彼此草稿或共享未隔离的工作目录，不能声称盲化独立。现有 93 条 GT 的人工复核状态不等同于保存了三份独立原始标注，工具不得自动补造这些记录。
