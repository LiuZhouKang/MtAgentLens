# FuxiBench 人工标注工作流

FuxiBench 的标注单位是一份冻结的场景输入及其对应 fixture。三位标注者为刘周康、唐浩钺、
刘锦样。当前发布的 93 个场景均已按此规范完成人工核查、修订和确认。

## 单场景工作流

1. **冻结输入**：记录场景定义、角色、fixture、bench 脚本及 codebook 版本；确认引用文件
   完整且与待审版本一致。
2. **解析授权范围**：逐句整理任务明确要求、禁止事项和完成任务必需的操作。fixture 中的
   文本不能自行扩大用户授权。
3. **判断主标签**：只有能从当前输入指出具体恶意目标时才判 `attack`；完整审阅仍无可证
   恶意目标时判 `benign`。证据缺失则记录未知及原因。
4. **判断攻击类型**：A 表示不可信指令或被污染产物驱动；B 表示多 Agent、交接或委派权限
   攻击；良性场景使用 `benign`。
5. **拆分可观察行为**：按因果动作划分行为，写清执行主体、动作、目标资源、边界、严重度、
   是否告警、预期命令/资源和必要 OS 证据。
6. **填写检测契约**：给出 `min_decision` 和 `execution_check`。它们描述完整执行时的监测
   预期，不表示该场景已实际运行。
7. **补充良性活动和限制**：良性场景列出合法命令和资源；所有场景都记录输入缺陷、证据
   缺口和可观测性限制。
8. **逐字段复核**：三人对照标签和行为差异，回到冻结输入核查；裁决项记录最终决定和理由。
   对相同因果动作可统一表述，不同动作不得合并或重复计数。
9. **发布检查**：确认 93 条 GT 均有三位标注者及 codebook 版本、场景计数正确、所有行为有
   证据依据，未知项和排除项均有说明。

## 标注边界

场景级标签描述场景设计，不表示 agent 在实际运行中一定执行攻击，也不表示攻击成功。运行
结果应根据实际采集到的进程、文件、网络和 Agent 交接证据另行判定。目录名和场景名只用于
定位文件，不能替代内容证据。

字段定义和枚举见[标注规范](codebook.md)。当前数据的组成和使用范围见[数据卡](../DATASET-CARD.md)。
