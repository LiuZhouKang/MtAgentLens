# 身份解析与证据归因：论文方法说明

身份解析回答“哪些观测属于同一个主体”，归因回答“哪些事实关系支持对目标行为的解释”。两者共用观测证据，但采用不同评价对象。本页统一术语和写作结构，结果与图表分别由 [IdentityBench](../../results/identity/README.md) 和 [AttributionBench](../../results/attribution/README.md)维护。

## 1. 身份解析：选择性赋值

MtAgentLens 以 PID 和启动时间识别进程代际，再结合进程谱系、TLS 参与关系与会话提示建立身份绑定。进程、连接和逻辑 Agent 的粒度不同：当同一进程承载多个会话时，没有会话锚点的动作可保留未知，不强行归给其中一个 Agent。

因此，评价应同时回答：

- 获得身份承诺的观测有多少，即赋值覆盖。
- 已作出的身份关系是否与参考一致，即已赋值子集的配对指标。
- 在全部参考已知单元中保留了多少同主体关系，即全参考配对指标。
- 是否错误合并不同主体，或将同一主体拆散。

当前实验在 30 个多 Agent 场景中抽样 1,800 个单元，其中 1,675 个参考已知。Full 对 654 个单元赋值，覆盖 39.0%；其已赋值子集配对 F1 为 1.000。所有条件均未观察到错误合并配对。这里测量的是参考分区关系的一致性，不是 Agent 名称或角色识别准确率。

论文可围绕“证据充分时赋值，歧义时保留 unknown”解释设计，再以覆盖和关系一致性共同描述其效果。未赋值单元仍保留在身份视图中。Full 与 TLS 条件覆盖不同，不能据子集 F1 将两者描述为相同的端到端效果。

完整条件定义、抽样方法、分母、CSV 和图表见 [IdentityBench](../../results/identity/README.md)。[E5 合成微基准](../evaluation/e5-identity-microbenchmark.md)用于检查预声明拓扑上的解析规则，不替代真实工作流评价。

## 2. 归因：以关系证据组织调查

责任图将执行主体、资源、边界与观测关系连接，供调查者从目标行为追查相关意图、动作和传播证据。直接执行者、内容引入者、起源候选和根因主体分别表达，不从“执行动作”直接推出“恶意来源”。

关系图可包含分支和多个来源。顺序关系仅在证据支持时建立；图深、节点数和边数说明结构，不单独证明定位正确性。设计约束见 [ADR-0017](../../../docs/adr/0017-evidence-bounded-attribution.md)。

当前冻结 suite 已交付关系、执行者和逐条原始记录，但 root/entry/ranking 的预测字段不足以形成可评分的根因结果，AttributionBench 标记为 `not_estimable`。论文可以用可追溯关系说明调查支持能力；定量 Root@k、Entry 和 Chain 正确率需匹配的预测与独立运行级参考。

指标输入及定义见[根因指标定义](根因指标定义.md)，本次可用产物见 [AttributionBench](../../results/attribution/README.md)。

## 3. 论文组织建议

方法部分先解释身份粒度、绑定依据与 unknown，再解释目标行为、证据关系及归因输出。实验部分先报告身份赋值覆盖与一致性，随后单独说明归因 suite 的可评价范围。检测指标、身份指标和根因指标分别命名。

使用[主张与证据矩阵](claim-evidence-matrix.md)定位正式结果；[修订要点](修改说明-草稿.md)对应正文和回复材料。原始审稿意见保存在[论文原件](../../../docs/paper/originals/README.md)。
