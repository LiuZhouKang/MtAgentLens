# IdentityBench：多智能体身份赋值与关系一致性

> **审稿意见 2a · 30 个多智能体场景 · 1,800 个抽样单元 · 2026-10-29**  
> 本页提供实验设计、人工复核参考、结果解释与可复核数据。最终身份标签由刘周康、唐浩钺、刘锦样核查、修订并确认。结果来自已有冻结运行与身份视图。

## 1. 核心叙事：证据约束下的选择性身份赋值

**MtAgentLens 将身份解析设计为选择性赋值：对能够建立明确身份绑定的单元作出身份承诺，对证据不足或绑定存在歧义的单元保留 unknown。** 这一策略使确定关系与未决关系分别进入可检查的输出，为后续责任分析保留身份判断的证据依据。

本实验中，所有条件均未观察到错误合并配对；TLS、对话和完整条件在已赋值子集上的配对 F1 均为 **1.000**。完整条件的身份赋值覆盖为 **39.0%**，体现了当前证据与完整约束下较保守的身份承诺范围。TLS 条件则在保持已赋值子集一致性的同时，覆盖 **74.2%** 的参考已知单元。

### 如何理解 full 的 39.0%

**39.0% 表示获得身份承诺的比例，不是事件采集率，也不表示其余观测被丢弃。** Full 视图保留全部 1,800 个抽样单元，并为其中未赋值的单元记录 unknown 及其原因；在 1,675 个参考已知单元中，654 个获得身份赋值，其余保持身份未决。

因此，论文可以把 full 的结果组织为：**在完整证据约束下维持保守的身份承诺，并将未决身份显式暴露给后续分析。** 已赋值关系的一致性和赋值覆盖共同描述这一行为，二者应并列报告。

### 可以突出呈现的三项结果

1. **身份承诺的一致性。** 本参考中所有条件的 false merge 均为 0；C2/C3/C4 已赋值子集的配对 P/R/F1 均为 1.000。
2. **可比较的承诺范围。** TLS 条件赋值 1,243／1,675 个参考已知单元（74.2%）；完整条件赋值 654／1,675（39.0%），呈现不同身份约束下的选择性赋值结果。
3. **可追溯的未决状态。** Full 将未赋值情况区分为进程身份未建立与消息歧义；这些单元仍保留在身份视图中，便于核查、补充证据与后续处理。

全文以“选择性身份赋值及其 precision–coverage 特征”为主线。这里的“一致性”指与本参考的分区关系一致；实验数值和评价范围在后文统一给出。

**表注。** 参考已知集合 N=1,675；125 个参考未知单元不参与计分。全参考 F1 将每个预测未赋值单元视作独立 singleton；已赋值子集 F1 只评价获得赋值的参考已知单元。五个配置在该参考集合中均为 FP=0、配对 precision=1.000。分数刻画分区一致性，不等同于 agent 名称／语义角色的分类准确率。

### 为什么同时报告两种 F1

全参考 F1 衡量**系统在整个可评价集合中保留了多少身份关系**；已赋值子集 F1 衡量**已经作出身份承诺的关系是否与参考一致**。两者共同描述赋值范围与关系一致性。

例如，C4 在 654 个已赋值单元内部保持了 2,765 个正确同 agent 配对，对应子集 F1=1.000；其余 1,021 个参考已知单元未赋值，全参考计分因而包含更多拆分，F1 为 0.280。两种结果描述不同的评价范围，可以同时成立。

C0 的全参考 F1 为 0.727，C2 为 0.712；C4 的全参考 F1 更低。因此本实验适合阐明身份赋值的选择性与可解释性，结果不作“full 在所有身份指标上最好”的排序。

## 4. 设计：用同一批跨层单元比较身份视图

### 4.1 研究问题与条件

本实验回应意见 2a 中关于进程、TLS 会话、对话信息和子智能体边界融合的量化要求。五个条件在相同场景与抽样单元上输出身份分区：

| 条件 | 视图与信号 | 实现说明 |
|---|---|---|
| C0 | 进程实例 | 使用 PID＋进程启动时间，区分 PID 复用 |
| C1 | 进程实例与 PPID 祖先搜索 | 使用祖先搜索控制路径；当前导出中发生元数据缺失回退 |
| C2 | TLS 与进程树身份视图 | 生产解析路径保留 TLS／进程树，移除 conversation 映射、原生调用观察及 delegation 约束 |
| C3 | 加入对话及原生调用观察 | 对话信息可见，不启用 delegation 约束 |
| C4 | 完整身份视图 | 在 C3 基础上加入 delegation 约束 |

代码入口：[identity/view.rs](../../../collector/src/responsibility/identity/view.rs)。C0/C1 是控制路径，C2–C4 是生产解析器的不同信号视图；条件名称中的“＋”对应实现中的信号开放与约束变化。

### 4.2 样本与参考

每场景按时间戳和 unit ID 确定性抽取 20 个 message、20 个 intent、20 个 action；协议允许额外纳入共享进程多对话相关单元，本次最终均为 60 个。30 个场景各有一次源运行，合计 1,800 个单元。

| 观测层 | 抽样数 | 参考已知 | 参考未知 |
|---|---:|---:|---:|
| Message | 600 | 562 | 38 |
| Intent | 600 | 563 | 37 |
| OS action | 600 | 550 | 50 |
| **合计** | **1,800** | **1,675（93.1%）** | **125（6.9%）** |

参考中的 1,243 个单元匹配 runner 声明启动进程，432 个通过进程祖先关系匹配。最终 actor／unknown 标签由三位标注者逐单元核查、修订并确认；人工复核后的参考身份分区用于本次评分。29 个场景具有参考已知单元；`benign-multi-incident-response` 的 60 个单元全部保留为 unknown，不贡献配对计数。

## 5. 机制解读：跨层身份承诺如何形成

### 5.1 进程粒度与逻辑 agent 粒度存在差异

C0 覆盖全部参考已知单元，但仍有 7,302 个同 agent 配对被拆开，错误拆分率为 42.9%。这反映了进程实例与逻辑 agent 身份之间的粒度差异：一个逻辑 agent 的相关行为可以分布在多个进程上。该观察为跨层身份融合提供了直接的问题背景。

### 5.2 TLS 条件呈现广覆盖的消息与意图赋值

C2 的 1,243 个已赋值参考单元包括全部 message、intent 参考和 118 个 action；其已赋值子集配对 P/R/F1 均为 1.000。这一结果适合用于说明：在当前观测与参考下，解析器能够形成与参考一致的消息—意图—部分 OS 动作身份分区。

| 配置 | Message 赋值／562 | Intent 赋值／563 | Action 赋值／550 |
|---|---:|---:|---:|
| C0／C1（各自） | 562 | 563 | 550 |
| C2 | **562** | **563** | 118 |
| C3／C4（各自） | 284 | 252 | 118 |

这里的子集一致性是该配置实际输出的性质，不单独作为相对基线提升的证据。覆盖与全参考指标共同保留在主表中。

### 5.3 对话视图使消息歧义进入显式输出

C3/C4 相比 C2 多出 589 个未赋值单元：278 个 message 与 311 个 intent，导出原因均为 `ambiguous_message`。另有 432 个 action 保持 `process_not_assigned`。因此系统的未赋值状态能够分解到具体观测层和原因，而不是只有一个无法解释的 unknown 总量。

论文可以据此说明**身份结果的可诊断性**：读者能够区分进程身份未建立与消息绑定歧义，进一步追溯需要补充的观测证据。reason 是解析器的状态记录；其存在不单独证明每次未赋值都属于预期安全决策。

### 5.4 这组实验对论文贡献的价值

- **提供跨层量化依据：**统一评价 message、intent 与 OS action 的身份组织关系。
- **展示身份承诺的一致性：**在报告覆盖率的同时呈现已赋值子集的参考一致性及实际错误合并计数。
- **使不确定性可观察：**将身份未赋值原因与单元类型、信号配置关联起来，支持复核和诊断。
- **给出可复用的评价方式：**全参考与条件指标并列，既保留系统整体关系保持，也呈现已承诺部分的质量。

这些贡献围绕系统输出的可解释性和可核查性展开；已有结果没有量化出相对基线的错误合并下降。

## 6. 可直接用于论文构思的文字

### 6.1 结果段示例

> MtAgentLens 采用证据约束的选择性身份赋值策略：在身份绑定明确时输出身份分区，在证据不足或消息绑定存在歧义时保留未决状态。在 30 个多智能体场景的参考评价中，所有条件均未观察到错误合并；TLS、对话与完整条件的已赋值子集配对 F1 均为 1.000。TLS 条件覆盖 74.2% 的参考已知单元，完整条件覆盖 39.0%。完整视图保留未赋值单元及原因标签，使后续分析能够区分已承诺的身份关系与尚待补充证据的观测。上述结果刻画了系统在身份承诺一致性与赋值覆盖之间的选择性行为。

### 6.2 机制讨论段示例

> 完整配置的设计取向是对身份合并保持审慎：只有明确绑定才转化为身份承诺，未建立或存在歧义的绑定保留为 unknown。实验中，完整条件在 39.0% 的参考已知单元上作出赋值，已赋值子集的配对关系与参考完全一致；其余单元以可追溯的未决状态保留。全参考计分将每个未赋值单元视作独立 singleton，因此 F1=0.280 同时反映了赋值覆盖收缩带来的关系召回成本。该成本与错误合并是不同的输出情形，联合报告 coverage、条件分区一致性和全参考 F1，可以清楚呈现这项设计的收益目标与实际代价。

### 6.3 对意见 2a 的回复组织

建议采用“**澄清身份视图 → 给出量化主表 → 解释跨层机制 → 简述参考与场景范围**”的顺序：

> 我们补充了进程、TLS、对话与委派信号下的身份分区比较，并联合报告赋值覆盖、配对 P/R/F1、B³ 及合并／拆分计数。TLS 与完整条件的已赋值子集配对 F1 均为 1.000，对应覆盖为 74.2% 与 39.0%；同时保留纳入未赋值单元的全参考 F1。我们进一步按消息、意图与 OS 动作分解结果，并将未赋值情况定位为进程身份缺失与消息歧义。该补充使身份承诺的关系一致性、覆盖和证据范围可量化、可解释。评价参考基于声明进程和祖先关系，实验结论限定于当前观测场景；共享进程内逻辑身份区分需要相应的独立参考支持。

使用时将表号、图号及算法段落与最终稿对应。适合使用“本参考中未观察到错误合并”“已赋值关系一致性”“显式表达不确定性”等表述；不将配对精度写成 agent 语义身份 accuracy，也不把较低覆盖自动解释为已证明的安全性提升。

## 7. 评价口径与统计说明

### 7.1 分母、配对与弃权

Coverage 的分母为 1,675 个参考已知单元，按单元汇总。配对只在同一场景内构造：TP 为参考相同且预测同分区，FP 为参考不同却预测合并，FN 为参考相同却预测拆分，TN 为参考不同且预测拆开。

- P=TP/(TP+FP)，R=TP/(TP+FN)，F1=2TP/(2TP+FP+FN)。
- 错误合并率=FP/(TP+FP)；错误拆分率=FN/(TP+FN)=1−R。
- 全参考指标为每个预测未赋值单元设置唯一 singleton；条件指标仅评价已赋值的参考已知单元。
- B³ 先按单元计算预测簇／参考簇交集的 P、R，再分别求均值及调和平均；表中为全参考版本。

本集合有 17,004 个同 agent 对和 31,445 个不同 agent 对，合计 48,449 对；配对计数不是独立实验次数。

| 配置 | TP | FP | FN | TN |
|---|---:|---:|---:|---:|
| C0／C1（各自） | 9,702 | 0 | 7,302 | 31,445 |
| C2 | 9,397 | 0 | 7,607 | 31,445 |
| C3／C4（各自） | 2,765 | 0 | 14,239 | 31,445 |

### 7.2 区间、检验和参考扰动

原指标采用场景级 bootstrap 5,000 次、seed=7，报告 pooled 配对 F1 的 95% 百分位区间。C0/C1、C3/C4 的点估计和抽样分区分别相同；其区间的微小差异来自原生成器使用了不同 Monte Carlo 抽样序列。

Holm 家族比较 C4 与 C0/C1/C2/C3，使用逐场景 F1 的双侧随机符号置换，2,000 次。C4 对 C0/C1/C2 的校正 p≈0.002，方向为全参考 F1 较低；C4 对 C3 为 p=1。bootstrap 与置换检验使用的统计量不同。原统计生成器对无可计分参考的场景使用零占位；展示 CSV 将此类分数留空，避免将占位解释成真实失败。

参考扰动以 10%／20% 概率逐单元替换为同场景其他已有 actor，各 20 次。C4 全参考 F1 的观察范围为 0.214–0.243／0.182–0.203；这是模拟扰动范围，不是置信区间或人工参考误差估计。

### 7.3 方法适用范围

选择性赋值是可由实现中的 Bound／Ambiguous／Unbound 分支核查的接口设计；39.0% 是当前运行与输入证据下的实测覆盖，不是预设目标。零错误合并属于本参考的观测结果，不单独证明更低覆盖必然带来更高安全性。

这些说明用于界定结果的适用范围，论文中可集中放在实验设置与限制段：

- **参考与拓扑。** 本参考以进程声明／祖先关系为证据基础，并由三位标注者人工复核、修订和确认；没有“同一进程实例、不同参考 agent”的已知配对，因而当前结果不独立验证共享进程内逻辑身份区分。30 个场景也不等同于另行设计的六拓扑受控压力矩阵。
- **条件行为。** C1 的 1,675 个参考已知单元均有 `no_agent_ancestor`、`process_metadata_missing` 标记，并回退到进程实例分区；因此本批次未分离出 PPID 的独立贡献。C3/C4 的抽样分区一致，表示本次没有观察到 delegation 约束的额外分区变化。
- **运行与参考独立性。** 每场景仅一次源运行，重采样区间不估计重复运行方差。配对指标评价分区关系，不验证预测分区名称或 agent 语义角色是否正确。
- **人工复核范围。** 最终标签经三位标注者核查、修订并确认。逐人原始投票记录未随当前冻结参考保留，因此不报告逐人一致率或 κ；所有结果均针对冻结后的最终参考。
