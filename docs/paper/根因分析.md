**根因正确性不能只用“链深 3–9”证明，要分四层测：检测对不对 → 根因主体/入口对不对 → 责任链对不对 → 去掉根因后攻击是否真的消失。** 文献里已有成熟的指标与实验协议，我们可以直接对齐，再补上“多智能体 + 安全”的特有部分。

## 一、正确性的四层拆解
| 层次 | 回答的问题 | 指标 | 我们现状 |
| --- | --- | --- | --- |
| L1 检测 | 是不是攻击 | TPR/FPR/AUROC | 已有 |
| L2 定位 | 根因是哪个智能体/哪个入口 | AC@1/@3、MRR、Entry@1 | 缺 |
| L3 解释 | 责任链对不对、全不全 | 链节点/边 P/R/F1、路径有效性、深度误差 | 只有深度与图规模 |
| L4 因果 | 去掉根因，攻击是否不再发生 | 反事实验证率 | 缺（可选） |


审稿意见 2 打的是 L2 和 L3：**“链深和图规模只能说明回溯能力，不足以证明定位结果正确。”**

## 二、其他文献怎么做实验
| 工作 | 任务 | 数据/规模 | 指标 | 关键设计 |
| --- | --- | --- | --- | --- |
| [BARO, FSE 2024](https://arxiv.org/abs/2405.09330) | 微服务 RCA | 3 个系统、多类故障注入 | **AC@k、Avg@k**（k=1,3,5，支持多根因） | 注入故障、GT=注入服务/指标、对比基线、参数敏感性、运行时 |
| [RCAEval, 2024](https://arxiv.org/abs/2412.17015) | RCA 基准 | 735 个故障、11 类故障、15 个基线 | AC@k/Avg@k，粗/细粒度 | 统一数据与评估环境 |
| [Groot, ASE 2021](https://arxiv.org/abs/2108.00344) | 工业 RCA | 952 个真实事故、5,000 服务 | **Top-1/Top-3**（78%/95%） | 生产数据、运行时延、错误分析（缺事件、多根因） |
| [Chain-of-Event, FSE 2024](https://doi.org/10.1145/3663529.3663827) | 事件因果图 RCA | 电商系统两个数据集 | Top-1/Top-3（79.3%/98.8%；85.3%/96.6%） | 消融 + 真实案例解释 |
| [AgenTracer, 2025](https://arxiv.org/abs/2509.03312) | 多智能体故障归因 | Who&When + TracerTraj | **agent-level / step-level accuracy**；w/ 与 w/o GT | 反事实重放 + 故障注入构造标注 |
| [TraceElephant, ACL 2026](https://doi.org/10.18653/v1/2026.acl-long.912) | 多智能体归因基准 | 完整执行轨迹 | agent 65.9%、step 30.3% | 3 人标注，Krippendorff α=0.72/0.64；完整轨迹显著优于只给输出 |


可以提炼出三条通用做法：

1. **排序式指标**：AC@k / Avg@k / Top-k，支持“根因是一个集合”（共谋环）。
2. **两级归因**：agent 级（谁）与 step 级（哪一步），必须分开报。
3. **注入/反事实**：GT 来自可控注入或反事实重放，而不是系统自己的输出。

## 三、我们计划怎么验证（E6）
**数据**：23 个 Type C 为主；可选扩到 60 个可观测攻击，用于入口/边界类型的泛化。每次场景一次冻结运行；另选 8 个场景重复 3 次估波动。

**真值**：在现有 GT v3 上新增 `root_agents`、`root_entry`、`key_chain`、`boundary_types`。3 位安全研究人员独立标注，**只看场景设计与原始日志，不看系统分数/PBC/告警**；分歧多数投票；报 Krippendorff α（目标 ≥0.7）。根因定义为“**最早把恶意载荷/意图引入工作流的智能体**”，下游执行者不算根因；共谋环标全部共谋者。

**指标**：

+ 主体：**RootAgent AC@1/@3（集合感知）**、MRR、RootSet P/R/F1。
+ 入口：Entry@1（严格：智能体+事件类型+资源；宽松：类型+资源）、Boundary-type Accuracy。
+ 链路：链节点 P/R/F1、链边 P/R/F1、Path Validity（是否构成入口→风险事件的连通路径）、Order Correctness、Depth MAE、Breakage Rate。
+ 身份（前置）：事件级 accuracy、pairwise P/R/F1、B³、false-merge/false-split、unattributed。
+ 弃权：Coverage、Selective Accuracy、Risk–Coverage 曲线。

**基线（关键）**：

+ Random；
+ **Max-PBC（最活跃智能体）**——直接检验“是不是把活动最多的当成根因”；
+ Degree centrality；
+ Alert-only（不回溯）；
+ Identity-ablated（仅 pid）；
+ No-taint chain（去污点边）。

**统计**：Bootstrap 10,000 次报 CI；AC@1 vs Max-PBC 用 McNemar，MRR 用 Wilcoxon，Holm 校正；按拓扑分组（委派链/共谋环/影子/交接/身份重放）。n=23，CI 会宽，文中明确“以效应量+一致性为主，不做强显著性声明”。

**因果校验（可选）**：抽 5 个单根因场景，移除载荷/禁用被控智能体/切断委派边后重跑，看风险动作是否消失，报 Causal Validation Rate。这比排序更接近“定位正确”的本意。

**错误分析**：身份错合并/错分裂、缺边、时间窗错位、多根因只报一个、入口歧义、角色映射失败；每个失败案例给图与链，不只报数字。
